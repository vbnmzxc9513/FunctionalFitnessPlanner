# 🏸 羽球功能性健身管理系統 (Badminton Functional Fitness)

這是一款專為**羽球愛好者與運動員**打造的智慧型功能性健身 Web 應用程式。我們不只是讓你流汗，更是針對羽球的發力機制、步伐敏捷度與動力鏈進行科學化的進化。

免費模板即可依球日、器材、時間與身體限制安排工作日體能；Gemini BYOK 為選配。課表提供保守的訓練起點，不能代替現場動作評估或治療建議。

---

## 介面與操作版型

以 Nike Training Club 的課程入口、Hevy 的訓練記錄與 TrainingPeaks 的週安排為參考，重新整理資訊層級：首次建立分三步；週總覽、每日內容與調整條件各自呈現；今日訓練聚焦一個動作，提供清楚組次與完成操作。淺底、深綠主色與一致字級取代原先多層藍紫卡片，動作庫使用篩選加緊湊網格。

手機、平板與桌機共用三個主要導覽。保存與安全判斷沿用既有規則；完整設計、來源與驗收見 [介面改版](docs/interface-redesign.md)。

## 目前的操作入口

主要導覽為 **今天／課表／紀錄**，帳號、語言與金鑰放在頁首「設定」。

- **今天**：建立課表後開始訓練，依序看暖身、主項準備、正式訓練和收尾。每次聚焦一個動作，可切換完整課表；「查看下一個動作」不會自動標記完成。
- **課表 → 本週課表**：上方「本週全盤計畫」顯示保存的週目標、實際分工與一到日安排；可選優先部位與無痛僵硬位置，重新排課後實際影響主項先後及暖身／收尾。選日、編輯、還原與調整排課條件也在此。「本週安排覆蓋」將髖腿、踝小腿、胸椎、肩部活動與蹲、髖鉸鏈、推拉、核心、步伐分開呈現，計算有安排的天數，並說明限制或缺項。它不是完成統計或失衡診斷。
- **課表 → 動作庫**：依暖身／主訓練／收操與搜尋找動作；「我的常用」可將同一動作放入多個用途清單，按帳號保存。收藏與啟用排課分開。編輯課表以階段、搜尋和短卡選取，取代長下拉選單。
- **紀錄**：先顯示待回報的翌日反應及最近實做，歷史統計收合；身體測量位於同頁另一分頁。

實做保持空白起始；「儲存紀錄」與「儲存並標記完成」分開。阻力、餘力與品質收在選填區，未知狀態不當成良好。昨日球量只在確認有打球後展開，調整預覽優先顯示差異。

正常週的免費模板在既有低負荷名額內輪替胸椎、髖和踝活動，器材允許時輪替上肢推拉；不為補齊表格增加時間、負荷或動作。治療限制、球量、疲勞與比賽減量優先；舊課表需明確重新排課才採用新策略。BYOK prompt 同時加入整週分布原則。

本週目標、保存方式與限制見 [每週全盤計畫](docs/weekly-plan.md)。完整設計見 [操作藍圖](docs/ux-blueprint.md)，驗收與限制見 [UX review](docs/ux-review.md)。

## ✨ 核心亮點與使用者體驗 (Highlights)

使用者在使用本系統時，將會深刻感受到以下與傳統健身 App 截然不同的亮點：

### 1. 🤖 真正「懂你」的 AI 專屬體能教練
* **精準診斷與排表**：AI 不是隨機抽卡給課表，而是會根據你輸入的「近期訓練目標（例如：想加強反手高遠球發力）」、每天可運動時間，以及歷史身體數值變化，進行全面評估。
* **知其然，更知其所以然**：AI 會生成一封充滿溫度的「教練總結與診斷信」，不僅鼓勵你，還會詳細解釋**「這週課表為什麼這樣排」**以及**「這些動作將如何幫助你在球場上達成目標」**。
* **對話式微調**：覺得今天排的腿部動作太多？可以直接在系統內輸入意見，請教練「微調與重抽」課表。

### 2. 🏸 深度結合「羽球專項」情境
* **動作原理連結**：每一個訓練主題都會清楚標示與羽球動作的連結。例如：告訴你練「保加利亞蹲」是為了**「強化大腿後側與臀部煞車能力，讓你在網前迅速急停而不失去平衡」**。
* **專項屬性訓練**：涵蓋核心抗旋轉（殺球力量傳導）、側向轉換（被動防守）、下肢爆發力（起跳殺球）等羽球極度需要的核心能力。

### 3. 🧠 會自動進化的「智慧動作庫」
* **自訂動作庫**：你可以隨時新增自己喜歡的動作（例如：高腳杯深蹲）。
* **AI 自動拆解動作**：當你輸入動作名稱後，AI 會**自動判斷該動作屬於哪一種肌群類型**（活動度、下肢、核心、上肢推/拉等），並**自動為你生成專業的教練發力提示**。排表時，AI 教練就會自動從你啟用的動作庫中為你挑選菜單。

### 4. 🔄 聆聽身體聲音的「動態難度反饋」
* **每週體感反饋**：每週結束時，你可以回報「太困難」、「剛好」或「太簡單」。
* **自動降階/增量**：系統會自動調整下週的組數與次數標準（分為減壓恢復期、功能性建構期、神經適應期），避免過度訓練或刺激不足。

### 5. 📈 專為持拍運動設計的「數據與成效視覺化」
* **不平衡監控**：除了體重與體脂，特別加入**四肢與軀幹肌肉量（左手、右手、左腳、右腳）**的追蹤，這對單邊發力的羽球運動員預防受傷極為重要。
* **GitHub 風格活躍網格 (Heatmap)**：視覺化呈現你每天的訓練活躍度。
* **肌群訓練分佈**：利用橫條圖展示下肢、核心、上肢推拉、活動度與全身爆發的完成紀錄。

## 🛠️ 完整功能清單 (Features)

* **[登入系統]** 支援 Google 帳號一鍵登入與 Firebase 匿名訪客模式。訪客紀錄也會寫入自己的雲端空間，可綁定 Google 保留紀錄。
* **[本日課表]** 可安排主要肌力、短協調、恢復或休息；AI 課表保存每項動作的組數、次數／時間、左右側及休息。
* **[AI 診斷室]** BYOK (Bring Your Own Key) 金鑰管理，支援自訂切換 Gemini 2.5 Flash / Pro 模型，保障隱私與彈性。
* **[身體數據]** 紀錄並圖表化展示體重、體脂、基礎代謝與各部位肌肉量趨勢。
* **[歷史成效]** 追蹤已載入範圍的訓練天數、累積動作次數、各月完成狀況與肌群分佈；支援載入更早紀錄。
* **[動作管理]** 內建 9 類、83 項雙語羽球動作，提供器材、分級、起始劑量與分類搜尋；支援新增、刪除、啟用／停用。
* **[雙語介面]** 支援繁體中文 (zh) 與英文 (en) 即時無縫切換。

## 實際訓練、恢復與下一堂建議

新增的回饋流程不需要 AI 金鑰：

1. 課前填寫「今天狀態檢查」：睡眠、疲勞、痠痛、症狀與球場負荷。先預覽，再明確套用今天的減量、恢復或休息安排；已完成的動作保持原處方。
2. 正式訓練時展開「記錄實際訓練」，填每組實做、兩側表現、阻力方式、重量記法、餘力與品質。空白不算完成，準備組不算正式組，單獨儲存不會自動勾選完成；可明確選擇「儲存並標記完成」。
3. 隔天到「紀錄 → 訓練紀錄」回報翌日反應。下一次打開同一動作的「下一次訓練建議」，查看維持、補紀錄、改善品質、減量或進階的理由。

進階需要最近 28 天至少兩個不同實際日期、相同器材與處方的合格紀錄，且兩側達標、仍有餘力、翌日沒有惡化。缺資料、疲勞、活動限制或接近比賽時不增加負荷；建議不會自動改動重量。徒手需描述變式，啞鈴區分每顆與總重量，彈力繩使用文字描述阻力。

登入後資料按帳號保存，免登入預覽保存在瀏覽器分頁，可隨課表一起採用到帳號。重新排課不改寫歷史處方；新增私人紀錄不會加入分享圖片／連結，也不會自動傳給 AI。近期載入上限為 12 週、480 筆訓練紀錄與 84 筆狀態；同一週課表動作格保留一筆可訂正紀錄。

完整操作與限制見 [訓練回饋流程](docs/coaching-loop.md)、[調整規則](docs/coaching-rules.md)及 [實作計畫](docs/coaching-upgrade-plan.md)與 [review 紀錄](docs/coaching-review.md)。新資料集合需要先部署本版 Firestore rules。

## 🚀 如何在本地運行 (How to Run)

1. 複製此專案到本地
2. 使用 Node.js 22.12 以上版本，安裝 lockfile 中的依賴套件：
   ```bash
   npm ci
   ```
3. 啟動開發伺服器：
   ```bash
   npm run dev
   ```
4. 為了使用 AI 功能，請至 [Google AI Studio](https://aistudio.google.com/) 申請 API Key，並於系統中的「設定」頁面綁定金鑰。金鑰僅儲存於瀏覽器 LocalStorage，不會寫入 Firestore；呼叫 Gemini 時會直接提供給 Google 進行 API 驗證。

預設開發路徑為 `http://localhost:5173/FunctionalFitnessPlanner/`。Firebase Web 設定可透過 `.env.local` 覆寫，參考 [.env.example](.env.example)。未覆寫時會連到原本的 Firebase 專案；測試使用 demo 專案與本機模擬器。

## 資料與操作行為

- 登出或換帳號會清空畫面狀態、表單與草稿。跨週時會切換到新的週課表。
- 每週反饋依固定基準難度重新計算，重複選相同反饋不會累加。難度會即時同步到其他裝置。
- 桌機與手機共用課表編輯控制。編輯、取消與儲存一致；若其他裝置先更新課表，舊草稿會被拒絕，請重新開啟編輯。
- 課表與當週統計快照使用 Firestore transaction 保存。移除動作不會刪除曾完成的訓練紀錄；本週完成率只計算當前課表中的動作。
- 上一份課表儲存在雲端，可於重新整理後復原。預設課表也能作為第一份備份。
- 測量紀錄以日期識別。選擇日期可載入原值；儲存時空白欄位保留既有值，數值會在前端與 Firestore rules 驗證。
- 月完成率按各動作的課表日期歸入月份，使用當週實際課表數量。舊資料優先使用已儲存的課表，無課表時使用 23 個動作的預設課表。
- 新完成紀錄保留實際完成日期與當時的肌群類別。舊紀錄沒有實際日期時使用課表日期；既有歷史無法還原成未曾記錄的實際訓練時間。
- 預設載入最近 104 週範圍的紀錄與 365 份測量，歷史／數據頁可載入更多。
- 訪客綁定新的 Google 帳號時保留 UID。Google 帳號已存在時會匯入訪客紀錄，保留既有帳號的同日期測量／同週課表、合併已完成紀錄及動作庫。中斷時可在同一瀏覽器工作階段重試。
- Gemini 金鑰是瀏覽器範圍設定，登出後仍保留；可在設定頁清除。排課時會把已載入的身體數據、訓練歷史及輸入訊息傳給 Google Gemini。

## 檢查與模擬器

```bash
npm run check
npm run test:integration
```

整合測試需要 Java 21，會自動啟動 Auth／Firestore 模擬器，使用 `demo-fitness-planner` 專案。測試涵蓋資料隔離、驗證規則、並行完成寫入、反饋、原子保存與復原、測量更新、訪客匯入，以及桌機／手機操作。瀏覽器測試會阻擋外部服務請求，不會寫入正式 Firebase 或呼叫 Gemini。

手動開發模擬器時先執行 `npx firebase emulators:start --project demo-fitness-planner --only auth,firestore`，再於 `.env.local` 設定 demo Firebase Web config 及 `VITE_USE_FIREBASE_EMULATORS=true`，啟動開發伺服器。請勿在測試中登入正式 Google 帳號。

## 部署

main push 的 GitHub Actions 會先執行 lint、單元測試、模擬器／瀏覽器測試及 build，再發布 gh-pages；PR 也會執行同樣的檢查。Cloudflare 建置使用 `CF_PAGES=1`，亦可透過 `VITE_BASE_PATH`、`VITE_SITE_URL` 指定路徑與 canonical URL；robots.txt 和 sitemap.xml 會隨建置生成。

GitHub Pages 部署**不會更新 Firebase rules**。本次新增的資料驗證規則需由 Firebase 專案管理者另行執行 `npx firebase deploy --only firestore:rules` 才會套用到正式資料庫；規則已在模擬器驗證。

本次動作庫／策略更新改寫排課 prompt、加入實際球日與前次課表上下文、擴充每項動作處方 schema 並驗證回應。Gemini endpoint、BYOK 與重試方式維持既有流程；模型設定尚未接入實際生成呼叫，其餘 API 問題不屬此次變更。


## 羽球動作庫與新排課策略

- 內建 9 類、83 項動作：動態暖身、下肢、上肢、核心／呼吸、爆發力、步伐、反應、拉伸／滾筒與心肺。完整動作說明見 [動作庫文件](docs/badminton-exercise-library.md)，[CSV](docs/badminton-exercises.csv) 可供整理。
- 進階動作預設停用；排課會再依器材、搭檔、經驗及肩部限制篩選。沒有藥球的菜單不安排藥球投擲；未知按壓手法與名稱含糊的筆記不作可操作動作。
- 教練頁可輸入每週球日（包含週末）、每場時間與強度、器材、搭檔、訓練經驗、比賽日期、治療限制和恢復紀錄。這些偏好於排課時按帳號保存在本機瀏覽器，換裝置不會自動同步；生成時傳給 Gemini。未填資料保持未知，不推測傷害診斷。
- 每週優先安排 1–2 次主要肌力與短協調，再依球量、恢復、連續球日和比賽日期安排短課或休息。反饋不再直接要求增加高衝擊或動作複雜度；短中長期、恢復與賽前減量策略見 [策略文件](docs/planning-strategy.md)。
- AI 產生 `prescriptions`，每筆含 `id / sets / value / unit / restSeconds / perSide`；必須對應當天已啟用且符合條件的 ID。前端檢查五個有效工作日、劑量、估計時間、額外跳躍量；不合格回應不會保存。估時與跳躍上限是編排約束，不能取代個別恢復或醫療評估。
- 新預設範例為徒手腿力、步伐及恢復組合，共 23 個槽位。舊課表 ID 與無處方資料仍可讀取；無快照的舊歷史仍以舊版 23 個槽位計算，不改寫完成紀錄。
- 本週 AI 處方按儲存內容顯示，不因全域難度變更而自動增加跳躍量。要調整本週劑量可在教練頁重新生成；移除動作時會清除孤立處方。

### Firestore 上線注意

新課表多了可選的 `day.prescriptions`。先由 Firebase 管理者部署此版本的 `firestore.rules`，再使用新排課功能；既有課表不需資料搬移。GitHub Pages 工作流程只發布前端，不部署資料庫規則。

```bash
npx firebase deploy --only firestore:rules
```

自動測試使用 Firebase 模擬器與攔截的 Gemini 回應，包含桌機／手機填寫條件、動作搜尋、生成、保存及重整後處方顯示，不呼叫正式 Gemini 或寫入正式 Firebase。


## 每日暖身、順序與收尾

「今日課表」依暖身／主項準備、協調與步伐、主要肌力、輔助、輕恢復、收尾分區，顯示動作順序、各區預估時間、組數、左右側與休息。準備組獨立顯示在暖身區，但不增加完成次數；正式組仍由原動作記錄。

AI 為每一天提供 `sessionType`、`warmupNote`、`cooldownNote`，每項處方提供 `phase`，需要準備組時附 `preparation`。訓練日須有實際暖身，第一個主要肌力須有輕量準備組；恢復日可以短做，休息日不必額外暖身或收操。完整課表最多八個不同動作，時間包含準備組、雙側、休息與轉換。

手動編輯可調整階段和同階段內的先後順序；既有完成記錄按原 ID 保留。舊課表以動作分類顯示階段，不自動補不存在的動作或準備組，重新排課才會取得完整的個人安排。

Firestore 使用同一筆 transaction 保存週課表、每日兩份 `planDays/{week}-D{day}-P{part}` 驗證資料和進度快照。每份每日文件驗證四項處方，兩份涵蓋最多八項。新版保存加上 `validationVersion: 1`，週文件用 `getAfter` 核對同次提交內容，避免整週詳細驗證超過運算上限。保存、還原和訪客匯入皆寫入這些驗證資料；舊版無階段課表仍可保存，不需要搬移歷史。需部署此次新版規則後使用新前端。

## 免費排課與分享

首頁可直接填球日、時間、器材與優先目標，使用免費模板產生五個工作日的課表，不需登入或 Gemini 金鑰。模板採固定規則；文字目標只保留作偏好，不當作已理解的限制。比賽減量、器材與身體限制仍優先；無法解讀的健康限制會採休息。規則及限制見 [模板排課](docs/template-planner.md)。

未登入的預覽與勾選保存在這個分頁的 sessionStorage，重整可保留。選擇登入保存後，預覽綁定所選 UID；空白週可自動採用，已有課表須明確選擇是否取代。完成紀錄與課表原子儲存，登出成功後清除尚未採用的預覽。

每日課表可下載 PNG 或複製公開唯讀連結。分享採動作庫 ID 與劑量白名單，不帶個人資料、自由文字、健康資訊、日期、帳號、完成紀錄或金鑰；自訂／非動作庫動作不能分享。圖片由瀏覽器本機產生，連結內容放 URL fragment，詳見 [分享規則](docs/sharing.md)。

教練頁預設免費模板，BYOK 是進階選項。免費排課不呼叫 Gemini；只有選擇 BYOK 時才查詢可用模型／生成課表。本機使用成效計數不上傳，並非全站分析資料。

## 選配 App AI 體驗

`functions/` 提供受控 callable：Google 登入、App Check、Secret Manager、每帳號每 UTC 週一次嘗試、全站每日上限、固定模型與結果驗證。**預設關閉，Pages 發布不會部署或啟用付費 AI 後端。** 啟用需要專案專用金鑰、計費設定、App Check 及額度，步驟見 [AI 體驗](docs/ai-trial.md)。

本機驗證可執行 `npm ci --prefix functions`、`npm run build --prefix functions`，再以 `GCLOUD_PROJECT=demo-fitness-planner` 載入入口。單元測試使用假交易與假 Gemini，不接觸正式 AI。CI 驗證後端建置，但只自動發布前端；不會開啟計費資源。

分階段的驗收標準見 [推廣功能計畫](docs/promotion-plan.md)。
