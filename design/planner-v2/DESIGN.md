# Fitness Planner 課表體驗：完整設計草案

狀態：PNG 與獨立原型；未修改 src/，未更新正式網站。保留既有藍／紫色系與「今天、課表、紀錄」三個底部分頁。

## 1. 頁面只負責一件事

「課表」取代「本週課表／日期課表／週計畫」等平行概念。日期切換決定看哪一週，不另外建立一套「本週」產品。日期範圍可以跨週，首頁按實際日期顯示。

- **課表首頁**：這週排了什麼；兩個入口「手動排課」「自動排課」；次要工具為動作庫、分享與草稿。空白狀態同樣提供兩個入口，免先搞懂動作庫。
- **手動排課工作台**：選日期 → 每天加入動作／改組次 → 檢查後套用。加入過程是草稿，不能即時覆蓋既有課表。電腦左邊日程、右邊動作搜尋；手機先編排，再進全頁挑選器。
- **自動排課互動**：日期 → 目標／時間／球日／器材 → 身體狀態／加強部位／偏好 → 預覽。免費固定規則是預設，不要求 API key。「自動」不等同必須付費 AI。
- **共用課表預覽**：每天安排、時間、簡短理由；展開才看八區日期與手選採用明細。主動作為「套用到課表」；手動與自動結果都可編輯、分享。
- **分享與匯入**：分享所選 N 天為副本 → 對方免登入預覽 → 每個來源日對應一個新日期 → 處理衝突 → 確認匯入 → 查看結果／撤銷。

## 2. 手動找動作的方法

不做一個永無止盡的下拉選單。搜尋支援動作名稱、常見別名與身體部位，例如「腿拉伸」「胸椎」「前鋸肌」。

第一層是動作類型：肌力訓練、動態拉伸、靜態／放鬆；這與要加入的暖身／訓練／收操階段分開。第二層是部位：肌力顯示腿／胸／背／肩胛／核心；拉伸顯示胸椎／肩胸／髖／腿部／踝小腿。需要時再展開臀、腿前、腿後、內收肌、前鋸肌、旋轉肌群等細分。跨層篩選採 AND，同一部位層多選採 OR，畫面要顯示目前篩選條件與清除入口。

個人常用、收藏與近期使用可以作為搜尋起點，但不改動動作的原本安全／器材分類。每個動作卡只放名稱、部位、器材與加入控制；教學與組次另開詳情。長按是捷徑，也必須有可見「編輯／詳情」入口。順序可用上下移動，拖曳為選配。

挑選器顯示「加入到 10/19 · 暖身／訓練／收操」、已選數與「加入 N 個動作」。勾選只是暫存；按加入才更新該日草稿；加入後顯示成功回饋與可復原。零選擇時不可按加入。

手動排課預設不偷加動作。提供明確的「加入我的每日八段拉伸」捷徑；是否使用由使用者決定。系統提醒時間或模式偏重，但不擅自更換手選動作。

## 3. 自動排課怎麼減少猜測

日期與可用星期分開：日期範圍是規劃範圍，體能可用日是能安排哪些天；球日是另計的負荷。時間寫「可用上限」，結果並列實際預估，短恢復日直接顯示理由。

疲勞、無痛僵硬、疼痛／治療限制分開。沒有填健康狀態不能被當成正常無限制；「沒有／有／不確定」要明確可選。有相關限制時展開必要資訊，不把復健判斷當互動測驗答案。

偏好動作是系統必須優先嘗試安排的選擇，最後用「已安排／未採用＋原因」交代；不能只在問卷說有選到。預覽有漏選時直接顯示摘要與返回調整，不用翻長篇教練說明。

## 4. 分享 N 天與匯入日期的規則

### 分享

- 可選一日、多日或整段；N 是實際分享的日數。勾選休息日也算一日，預覽須標為休息，不悄悄省略。
- 分享是不可變的副本，接收者的修改不回寫原作者；原作者後來修改自己課表，也不暗改已發出的副本。若要更新，另建分享版本。
- 內容含順序、暖身／技能／主訓／輔助／收操／恢復、計畫劑量、休息與必要準備組。不含實做紀錄、實際重量、健康備註、帳號身分與私有回饋。
- 自訂動作如納入分享，只帶經長度與字元驗證的名稱、最小描述與組次；收件者建立新 ID 副本，不污染既有動作庫；不能靜默丟掉不支援的動作。第一階段若未支援，建立連結前必須說明並阻擋不完整分享。

### 收件者

- 打開連結即可看「N 天、每一天主題、時間、器材」，不用登入或先填問卷。
- 顯示來源「第 1 天、第 2 天、第 3 天」，不硬套原作者的實際日期。來源相對間隔可保留，原作者的原始日期不必公開。
- 「保留原間隔」依一個開始日期提出建議；「逐天指定」逐列改日期。每一列永遠保留來源日、主題、目的日期三者，避免只選 N 個日期卻不知道如何對應。
- 日期數須等於所選來源日數；禁止重複、過去日期與不存在的日期。可不連續，可跨週，最多沿用目前產品 28 天邊界。
- 目的日空白：新增。目的日有未開始課表：換日期或明確替換。目的日已有完成／實做紀錄：保留，不提供覆蓋，必須換日期或取消該來源日後重新確認日數。
- 不提供自動合併兩堂課，避免動作數／時間／工作量被悄悄疊加。取消不更動任何目的日。
- 確認頁列出新增 N 天、替換 N 天、確切日期與保留的紀錄。最後一次確認才寫入；寫入前重新檢查版本與紀錄，任何衝突都回到預覽，不部分匯入。
- 未登入可存目前裝置；跨裝置同步稍後再登入。匯入不等於完成；不沿用分享者的完成勾選。
- 撤銷只恢復沒有後續修改／新紀錄的日期；若已開始訓練，不覆蓋新事實。需有可檢視結果，不保證一鍵強制全還原。

## 5. 視覺與漸進揭露

保留現有天空藍與靛紫主色；用白底、少量邊框與固定字級建立層級。主頁先看到模式入口與每日安排。目標分析、八區明細、手選明細是第二層，不搶主畫面。

一次畫面一個主要提交動作。主要按鈕用具體結果：「加入 2 個動作」「檢查 3 天課表」「套用到課表」「確認匯入 3 天課表」，避免所有階段都只寫「下一步」。草稿／預覽／已安排／有紀錄以文字和圖示呈現，不只依顏色。

固定底部操作需留足頁尾空間、支援瀏海安全區；主要可點區域至少 44×44 CSS px。320 px 不橫向溢出；大螢幕才使用左右工作區。鍵盤焦點、讀屏名稱與狀態通知需在實作與互動測試驗證，不能單靠 PNG 宣稱合規。

## 6. 現有架構需要的改動

現有 sharing.js 的公開格式是單日 v1、最多 8 動作與約 6000 字元連結；SharedWorkout 目前主要是唯讀。不能只把按鈕換名字就宣稱支援多日匯入。

建議新增獨立 v2 多日分享快照格式，不破壞 v1 舊連結。v2 需要 days（來源順序、相對間隔、主題、階段與劑量）、版本與內容驗證。長課表應用短分享 ID 載入快照，不能無限制塞在 URL。快照採最小資料、隨機不可列舉 ID；寫入與讀取權限另設，禁止任意列舉與私有資料外洩。建立分享與匯入皆不呼叫 Gemini。

沿用既有日期 session／保護日期／原子套用邏輯；manual draft、auto preview 與 shared import 統一轉成同一個可驗證的日期課表，再套用。避免再建立另一套週課表儲存模型。

## 7. 分階段實作順序（本次不執行正式功能）

1. 課表首頁重整＋唯讀每日詳情；移除平行與重複入口，保留舊資料可讀。
2. 手動工作台＋用途／部位標籤搜尋＋同一份草稿／預覽／套用流程。
3. 自動互動共用日期選擇與預覽；維持現有排課與保護條件，改入口與資訊層級。
4. 多日分享快照＋唯讀接收頁＋日期對應＋衝突預覽＋原子匯入；保持舊分享相容。
5. 正式易用性測試、鍵盤與讀屏測試、320 px 與桌面回歸；確認無 P0／P1 後再發布。

每階段先做可單獨驗證的變更，不一口氣重寫整個 App。真人測試方法與門檻詳見 research.md；本次 sub-agent 只做模擬角色走查。


## 8. 審查後加入的實作門檻

原型仍有三項 P2，正式功能發布前必須完成：選取重繪保留鍵盤焦點、換頁聚焦標題；重複的編輯／加入按鈕及週切換有具體可存取名稱；保存／取消／錯誤有適當 status／alert 與欄位描述關聯。再以鍵盤、實機讀屏與任務型真人測試確認，不能只用 PNG 判定通過。
