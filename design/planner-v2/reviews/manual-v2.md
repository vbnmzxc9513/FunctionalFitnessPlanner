# 手動排課第二版獨立走查

日期：2026-10-19。角色與任務沿用 [manual-v1.md](manual-v1.md)：健身常客自行排週一、三、五，找腿／胸／背肌力、腿部拉伸、胸椎拉伸、前鋸肌，指定日期與階段，改組次、保留草稿、最後套用。

這是模擬使用者走查，加上本機互動原型的檢查；不是真人研究，沒有完成率、秒數、SUS 或滿意度分數。僅新增本報告與評估證據，沒有修改原型或產品。P0–P3 定義沿用 [research.md](../research.md)。本報告的 P1 是**這份互動原型**未能完成任務的判定，不代表正式產品存在同一問題。

## 這輪實際觀看與操作

用 `view_image` 重新看過第二版 [03-dates-manual](../png/03-dates-manual.png)、[04-manual](../png/04-manual.png)、[04b-day-view](../png/04b-day-view.png)、[05-pick-strength](../png/05-pick-strength.png)、[06-pick-stretch](../png/06-pick-stretch.png)、[07-exercise-detail](../png/07-exercise-detail.png)、[10-plan-preview](../png/10-plan-preview.png)、[04-manual-desktop](../png/04-manual-desktop.png)。沒有把第一版 PNG 當成第二版證據。

另以 Chromium／Puppeteer、390×844 視窗，經由可見按鈕操作 `prototype.html`。沒有以腳本直接寫入排課狀態；讀取原型狀態及本機草稿資料，僅用來交叉確認畫面行為。步驟如下：

1. 03 保留已選的 10/19、10/21、10/23，按「開始排 3 天」。編輯頁的動作列確實為零，沒有把 PNG 04 的示例內容當成新草稿初始狀態。
2. 週一訓練勾「分腿蹲」後直接「回到排課」，草稿仍是零個動作，沒有套用；再開選擇器顯示「已選 0 個」。
3. 週一訓練勾分腿蹲、側弓步，再按「加入 2 個動作」，兩者才進入草稿；另加側躺胸椎開書到暖身。
4. 切週三，從「胸」「背」及「找前鋸肌、旋轉肌群 → 肩胛」找到啞鈴地板推胸、單臂滑輪划船、彈力繩前鋸肌前伸。跨部位勾選維持三個，再按「加入 3 個動作」，均在週三訓練。
5. 切週五收操，選「動態拉伸 → 腿部」，加入徒手動態髖鉸鏈；目的地仍是週五收操，切類型沒有改日期或階段。
6. 嘗試編輯側弓步、儲存、保留草稿、同頁續編、檢查預覽、點日期詳情、返回週課表後重新整理。另以全新頁面，從空白草稿只加分腿蹲，走到「套用到課表」並開週一檢查結果。

主要操作與狀態證據記在 [manual-v2-checks.json](manual-v2-checks.json)。這些是原型檢查紀錄，不是真人測試量測。

## 仍阻擋完整任務的問題

### V2-1 — 保留草稿後重新整理，無法從畫面恢復草稿（P1，原 M1 的剩餘部分）

- **重現：**完成上述三天 →「保留草稿後離開」→ 週課表出現「繼續手動排課草稿」→ 點入可續編 → 返回週課表並重新整理。
- **證據：**重新整理前可續編三天；重新整理後 [週課表截圖](manual-v2-reload.png) 沒有續編入口。原型 `manualDraft` 為 null，但 `fitness_planner_design_draft` 本機資料仍存在。這是無法恢復，不是已證明底層資料被刪除。
- **影響：**「留在這台裝置」合理包含之後重新開啟；使用者完成保存卻找不到內容，核心的留待下次任務失敗。
- **最小修正：**啟動時讀取有效的本機草稿，恢復日期／動作與續編入口；只有保存成功才顯示成功訊息。若此輪原型只示意當次頁面暫存，則明確縮小承諾，並把跨次恢復留作未驗證項，不能稱已通過保留草稿。

### V2-2 — 草稿預覽的日期詳情打開既有正式課表（P1）

- **重現：**本次週一草稿是側躺胸椎開書、分腿蹲、側弓步 →「檢查 3 天課表」→ 點 10/19「自訂訓練」。
- **證據：**[日期詳情截圖](manual-v2-preview-detail.png) 卻顯示「全身肌力與穩定」、八段動態拉伸、硬舉、深蹲、划船，沒有剛排的分腿蹲與側弓步；狀態是「已安排・尚未完成」，主按鈕為「開始這天的訓練」。此時原型套用旗標仍為 false。PNG 04b 單獨作為正式日課表是清楚的，但接在草稿預覽後就錯用了其狀態。
- **影響：**檢查草稿時看到另一份課表，無法核對自己的安排，還會誤認已安排或進入訓練。原本清楚的草稿／正式區別，在跨頁操作時失效。
- **最小修正：**草稿日期詳情必須讀目前草稿，標「草稿預覽・尚未套用」，主操作為「返回檢查」或「修改這天」，保留日期與階段；不能使用正式日課表的開始訓練按鈕。

### V2-3 — 點第二個動作編輯，實際改到第一個動作；階段選擇未儲存（P1）

- **重現：**週一訓練先有分腿蹲、側弓步 → 點側弓步右側「編輯」→ 將組次改成 3×8、安排階段改為收操 →「儲存修改」。
- **證據：**[編輯頁截圖](manual-v2-wrong-edit.png) 打開的是「分腿蹲」，不是側弓步。儲存後分腿蹲成為 3×8，側弓步仍是 1×6；兩者都留在訓練，收操為空。這些內容保留在檢查紀錄中。
- **影響：**指定動作的組次與階段不能按意圖修改，還可能改到未打算變動的動作。這是本次草稿任務的錯誤，未觀察到正式完成紀錄被修改，因此不列 P0。
- **最小修正：**編輯入口攜帶日期、階段與動作識別，表單載入／儲存同一項；儲存時實際處理安排階段。回排課後應能直接看見指定動作的新組次與新階段。

### V2-4 — 有動作的手動預覽，卻稱每一天「不另排體能」（P2）

- **重現：**用 03 新建空白草稿，完成本次三天新增後檢查。
- **證據：**[手動預覽截圖](manual-v2-preview.png) 三天都寫「自訂・不另排體能」；在編輯頁，同三天已有動作，頁籤分別顯示 8、9、2 分。
- **影響：**無法知道系統是漏掉動作、把這天視為休息，或只是摘要錯誤；需退回逐日核對。PNG 10 使用既有示例時間，所以單看它不會暴露這個空白草稿流程問題。
- **最小修正：**摘要使用和編輯頁相同的計算結果。若時間尚未可估，顯示「已排 N 個動作・時間待估」，只有確實沒有動作的休息日才寫「不另排體能」。

### V2-5 — 按套用顯示成功，正式日課表仍是原來內容（P1）

- **重現：**另一個全新頁面從 03 新建三天空白草稿 → 週一訓練只加「分腿蹲」→「檢查 3 天課表」→「套用到課表」→ 點週一。
- **證據：**週課表顯示「已套用 3 天課表」，但 [套用後日期截圖](manual-v2-applied-day.png) 仍是八段動態拉伸／硬舉／深蹲／划船／呼吸，沒有分腿蹲。
- **影響：**套用成功訊息與使用者看到的課表不一致，無法判斷自己排的動作有沒有生效；核心套用任務未成立。
- **最小修正：**讓這份原型的確認操作更新對應日課表資料，週視圖與日詳情都讀相同結果；若套用仍是示意，按鈕回饋必須明說示意，不可聲稱已套用。正式資料寫入及衝突保護仍需另外驗證。

## 可以判定改善的部分與邊界

「加入動作」現在足夠明確：按階段旁的入口，勾選候選，按底部「加入 N 個動作」才寫進草稿；直接返回未把暫選加入或套用。日期頁籤與目的地標示可核對，實測胸、背、前鋸肌、胸椎及腿部動作都有可找到的路徑。畫面也持續提供「編輯」「往前／往後」等點按入口，不要求長按或拖曳；但排序、移除目前只回示意訊息，不能據此聲稱這些動作已完整實現。

本輪未發現可證明的 P0。原本三個 P2 的文案／狀態設計有明顯改善；重複標籤仍是 P3。**不能判定整個手動任務通過**：重新開啟草稿、正確編輯、草稿詳情及最後套用仍有上述原型接線問題。真正的紀錄保護、伺服器寫入、網路失敗、讀屏與鍵盤完整流程不在此次驗證範圍。
