# 推廣功能 review 結果

排課核心、首次使用流程、分享及受控 AI 後端由四個 sub-agents 分工實作，主 agent 已審查、修正並整合。

## 已修正

- 未登入且沒有待採用課表時，避免空物件週次存取造成首頁錯誤。
- 預覽在分頁重整後保留；登入採用時，合法的完成勾選與課表在同一個 Firestore transaction 儲存。
- 採用預覽綁定使用者 UID；已有課表須明確選擇取代，保留過去完成紀錄。未儲存預覽先保存／放棄，才允許訪客升級帳號。
- 登出成功後才清除預覽，失敗保留備份；監聽分享 fragment 與前後導航，避免顯示舊的分享內容。
- 分享內容由白名單重建；準備組說明使用公開通用文字，排除作者的原始自由文字。自訂動作拒絕分享，不默默刪掉它們。
- 分享控制放在當日動作後面，讓暖身與訓練順序先呈現。
- App AI 體驗在發送前／接收後核對本地與服務端週次，防止時區週界把比賽減量課表存錯週。
- 後端使用目前的 Firebase Admin／Functions 套件；新增後端依賴安全掃描為零已知漏洞。

## 已驗證

- 52 項單元測試，包含 150 種免費排課條件組合、限制／比賽期、分享隱私與格式、額度並行與失敗處理。
- 17 項 Firestore 模擬器整合測試，包含原子保存、訪客轉移、權限隔離與 server-only 額度設定。
- 桌機／手機操作：免金鑰預覽、重整、勾選、分享公開頁、登入採用、手動編輯與還原、BYOK 假回應、跨週、登出與英文。
- 本機 production build 的 PNG 匯出、無效 fragment 導航及手機尺寸檢查；未發現橫向溢出或 runtime 錯誤。
- 後端共享模組建置與 Node 22 入口載入；測試沒有呼叫正式 Gemini 或啟用付費資源。

## 正式啟用 AI 體驗前

後端程式與部署說明已完成，但共用 AI 服務預設關閉。尚需專案專用金鑰、計費與費用／呼叫上限、實際 App Check 註冊及真實 callable 驗證；詳見 [AI 體驗](ai-trial.md)。模擬測試不能代替正式 App Check 驗證。

免費模板是保守起始安排，不會解讀任意醫療或訓練文字、也不會因「太簡單」自動加重。成效計數只留在個別瀏覽器，不能用來宣稱全站轉換率。
