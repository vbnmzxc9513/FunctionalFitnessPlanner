# 每週全盤計畫

2026-10-15。沿用「今天／課表／紀錄」，週初規劃放在「課表 → 本週課表」最上方。

## 使用流程

1. 首次建立，或在週總覽按「調整本週目標」。選本週主要方向：全面基礎、協調與步伐、單腳穩定或整體肌力。
2. 依三步問卷確認目標與時間、身體感受、想做的動作；優先部位、無痛緊繃與肌肉痠分開填。詳見 [本週選課](weekly-selection.md)。
3. 產生免費或 BYOK 預覽，先看實際安排與候選結果，再確認套用；選擇與預覽都不會立刻修改現有課表。
4. 在「本週全盤計畫」看保存的方向、實際肌力／協調／恢復／休息天數、一到日分工與預估體能時間。肌力與協調可同日，球局不算體能完成或上述估時。
5. 選一天進入每日內容，查看暖身／準備組、主項與收尾搭配；可返回本週總覽。週末只呈現保存的球日與未編排體能，不擅自加課。
6. 週中記錄實做、睡眠與翌日反應；週末依主目標的追蹤提示回顧。重新排課仍保留已有實做與符合新課表的完成標記。

## 排課原則

- 主方向仍使用既有排課規則。優先部位調整既有主項順序與時間不足時的取捨，不因勾選直接提高單項組數，也不排除所有其他部位。核心優先時可把原有核心名額列為主要訓練。
- 保留一般升溫，再以當天第一個主項及相關僵硬偏好選一個現有暖身名額；主要肌力保留輕量準備組。暖身與雙側休息都計入上限，時間不足刪低優先工作。
- 無痛僵硬影響既有低負荷名額的輪替，可從合格候選使用胸椎、髖、踝、肩部舒適活動／短拉伸。選擇後估時可能不同，但不超過每日上限、不增加動作數。
- 治療／未知限制、麻木無力、恢復優先與比賽熟悉度守門先行；偏好不能把全休息／肩部有條件走路變成拉伸或正式訓練。不為補滿部位新增負荷或延長課表。
- 總覽的天數、每日主項、暖身與收尾只由實際課表推導；未涵蓋的偏好明說沒有安排，不宣稱已改善僵硬或達成目標。文字不是醫療評估。

## 保存與相容性

- 週課表可選 `weeklyIntent` 保存固定列舉的 focus、最多兩項 targetRegions／stiffnessRegions、球日、每日時間、比賽日期與可選的最多八個 weeklyExerciseIds；不保存肌肉痠、健康備註或實做。Firestore rules 限定欄位與界限。
- 初次載入帳號課表時，從該週快照還原這些設定；不從快照推定器材或身體限制。其餘條件仍依原帳號的本機偏好。跨裝置要再次確認器材與健康條件。
- 手動編輯、還原與訪客採用保留快照。新選擇尚未套用時顯示提示，總覽繼續使用已保存的設定。舊課表沒有快照時，明說週目標／球日未知，仍能查看實際安排。
- 分享仍使用原有 ID／劑量白名單，不含 `weeklyIntent`、僵硬偏好或私人紀錄。
- 先部署本版 Firestore rules，再發布前端。既有課表無須搬移。App AI 體驗仍預設關閉，不部署付費 functions。

## 驗證

110 項單元測試，含 144 種目標／僵硬／時間組合、主項與暖身變化、不直接提高組數、限制／疲勞／賽前不被偏好繞過、舊課表／週末、預覽快照、分享白名單與 App AI 輸入界限。

30 項 Firebase 規則與交易測試，含週意圖保存、編輯／還原及無效欄位拒絕。手機與桌機瀏覽器檢查選擇上限、七日總覽、尚未套用提示、重新整理與匿名採用；移除本機偏好後仍還原保存的週目標。既有分享、編輯、實做、每日調整、翌日回報與 mock BYOK 流程保留。
