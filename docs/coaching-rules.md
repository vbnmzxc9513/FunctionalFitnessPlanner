# 訓練紀錄、每日狀態與下一堂建議

這一版將課表的「預計做多少」和使用者的「實際做多少」分開。所有建議由本機規則計算，不需要 AI 金鑰。建議不會自動增加課表負荷；當日減量會先預覽，確認後才保存。

## 實際動作紀錄

每個週課表動作格只有一筆紀錄，ID 為 `週-D星期-動作ID`。同一格可以編輯訂正，但不會因此累積成兩堂訓練。實際日期獨立於課表星期，能記錄補練的日期；不接受不存在或未來的日期。

必填欄位保留明確的「未知」，不把空白轉成零或課表目標：

- 器材版本：徒手、啞鈴、纜繩機、彈力帶、其他。
- 重量基準：無重量、每支啞鈴、總重量、機台配重、文字阻力說明。`10 kg／每支啞鈴` 與 `10 kg／總重量` 不能視為同一負荷。
- 實際每組次數或時間。單側動作需分別填兩側；明確輸入零可表示該側停止或未完成。空白不能儲存為完成。
- RIR（餘力）、動作品質、症狀是否加重，以及隔日反應。未知餘力或症狀不能支持加量。
- 當時的課表目標快照：組數、次數／時間、單位、單側、階段、組間休息。後續修改課表不會改寫這個快照。

兩側欄位代表每組的兩側實際表現，不將兩側相加當作單側達標。隔日反應只在實際訓練日期過後可填；當天只能是「待回報」。

紀錄上限是資料格式限制，不是建議訓練量：每動作最多五組，次數／呼吸每組最多 500、秒數最多 3600、分鐘最多 120，重量最多 500 kg。非負數必須明確填寫；次數／呼吸限整數。

## 每日狀態

紀錄包含日期、睡眠、疲勞 0–4、痠痛 0–4、症狀、昨天球局分鐘與 RPE 0–10，以及今天球局強度。資料必須是今天的；昨天的狀態不能代替今天。昨天沒有打球時，分鐘填零，RPE 可未知。

| 條件 | 當日安排 |
| --- | --- |
| 症狀加重、新出現麻木／無力等警訊 | 停止尚未完成的訓練，聯絡治療／醫療人員 |
| 明確限制、肩部震波相關備註，或限制狀態不明 | 不增加負荷；只保留已知適合的低負荷原有動作 |
| 疲勞或痠痛達 4、睡眠少於 5 小時，或昨天球局負荷 ≥720 且疲勞 ≥2 | 恢復 |
| 疲勞或痠痛達 3、睡眠少於 6 小時，或昨天球局負荷 ≥420 | 減量 |
| 今天高強度打球 | 減量並取消額外未完成的跳躍、爆發與高強度步伐／反應動作；純影片預測可保留 |
| 關鍵資料未知或過期 | 狀態未知，不視為可以加量 |
| 完整紀錄、沒有上述條件 | 維持原安排，仍需遵守既有治療限制 |

球局負荷使用「分鐘 × RPE」作為簡單的訓練量提示。上述數字是保守的產品排課規則，**不是經醫學驗證的診斷界線、受傷預測或復出許可**。沒有疼痛、不痠或睡滿某個時數，都不代表治療已完成。

## 下一堂的建議

只對肌力型、以次數計量的主訓練／輔助動作提供增加建議；不將跳躍、步伐、反應、耐力、拉伸和準備組套用肌力加重規則。

需要最近 28 天內兩筆不同實際日期的真實紀錄，且同時符合：

1. 同一動作、相同預定目標（包含休息）、相同單位與單側設定。
2. 相同器材版本、重量與基準、阻力文字描述；不跨器材換算。徒手也需明確描述變式、支撐高度、深度或節奏；纜繩機需描述同一機台與設定，只有重量片數字不能支持進階。
3. 每一組的兩側皆達到目標下限，實際組數符合預定組數。
4. 動作品質良好、餘力至少 2、無症狀加重，且兩次隔日反應皆良好。
5. 今天狀態完整、沒有疲勞／痠痛達 2、臨床限制，以及賽前七日內減量期。臨床狀態缺漏視為未知；非空健康備註需人工確認，不以自由文字判定可以加量。

例如兩次都完成 `2 組 × 每側 6 下，目標 6–8 下，每支啞鈴 8 kg`，才建議下次**同重量每側 7 下**，不同時增加重量或組數。兩次所有組／兩側都達上限，才提示考慮最小重量增量、回到範圍下限；只有使用者已提供可用的重量增幅時，才顯示具體公斤數。徒手、彈力帶或其他文字阻力達上限後，需要人工檢視阻力變化，不會自動換算成公斤。

處方範圍若是單一數字，不發明新的次數上限。沒有足夠資料時，建議為維持、補紀錄或補隔日回報。改變目標／休息／器材後，需要重新累積可比較的紀錄。

## 當日調整的邊界

- 先預覽，再由使用者確認；不悄悄變動課表。
- 只改尚未完成的原有動作，不加入新動作，不改已完成紀錄或其處方。
- 減量以減少工作組為主；單組動作才減少該組目標。保留暖身與必要的輕量準備組；休息時間不縮短。
- 恢復保留原課表中的低負荷暖身、活動度、呼吸、輕鬆步行或影片落點預測；有臨床限制時不保留缺少分類的自訂／舊版動作。
- 停止訓練時移除尚未完成的工作。已完成的項目仍在課表中，不能藉此清除歷史。
- 休息日不升級成訓練日，恢復日不升級成肌力日。

## 開發契約

`src/domain/coaching.js` 提供：

- `validateTrainingLog(record, { today })`、`validateReadiness(record, { today })`：驗證並複製白名單資料；不合法時拋出 `INVALID_TRAINING_LOG`／`INVALID_READINESS`。
- `plannedSnapshot(dose)`：產生獨立且正規化的目標快照。
- `trainingLogId(record)`／`logId(record)`：穩定的每週動作格 ID。
- `evaluateReadiness(record, { today, healthStatus, healthNotes })`：`{ action, reasonCodes }`。`action` 是 `normal / reduce / recover / rest / unknown`。
- `recommendExercise(dose, exercise, logs, context)`：`{ code, reasonCodes, parameters, evidenceDates }`。`code` 是 `hold / record_more / complete_followup / improve_quality / reduce / rest / progress_reps / consider_load`；不修改輸入資料。
- `adaptDayForReadiness(day, decision, completed, exercises, lang, time)`：產生當日調整草稿，保留已完成項目。`completed` 使用既有 `dayN_ID` 格式。

以上資料屬個人訓練紀錄；不應加入公開分享連結或課表圖片，也不應在使用者沒有明確同意時送給 AI。
