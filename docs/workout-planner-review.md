# 排課、收藏與分享的實作 review

此功能沿用既有色系與三個主頁籤。本週課表先顯示週切換、並列的手動／自動入口與每日安排；收藏及動作庫放在列表之後。手動、自動問卷、日期對應與收藏詳情各自有清楚的返回與下一步。

檢查使用以下面向，並非正式認證或真人研究：

- 依 [ISO 9241-11 的使用性定義](https://www.iso.org/standard/63500.html)，檢查指定任務能否完成、是否有多餘操作、使用者能否理解結果。
- 依 [Nielsen 的使用性啟發式](https://www.nngroup.com/articles/ten-usability-heuristics/)，檢查狀態可見性、辨識優先、使用者控制及錯誤防止。
- 參照 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)，檢查鍵盤操作、焦點回復、欄位標示與可操作區域；瀏覽器檢查包含 44px 控制尺寸，不代表完整 WCAG 相容性驗證。

## Agent 分工與獨立審查

實作分為手動動作挑選、命名收藏、正式分享三項，由不同 agent 負責；主 agent 整合與 review。另以使用者角度進行手機畫面及真實瀏覽器流程審查。這是 agent 模擬，不等同真人訪談或滿意度調查。

實際發現並修正：

| 問題 | 修正 | 回歸驗證 |
| --- | --- | --- |
| 首次未登入畫面讀取空的遷移摘要而失敗 | 判斷摘要存在後才顯示 | 完整流程由全新瀏覽器情境開始 |
| 重新整理後器材設定遺失，草稿的動作變成不可用 | 依帳號範圍保留目前條件與每日時間 | 選啞鈴、加入動作、重整、續編並套用 |
| 手機選完動作要捲到底才能加入 | 固定可見的數量與加入操作列 | 320／390px 及桌面瀏覽器 |
| 切回「保留原間隔」沒有重算日期 | 按來源 offset 重算並清除舊預覽與替換同意 | 改單日日期後切回，確認恢復兩天間隔 |
| 手動輸入每日名稱套用後遺失 | 每日名稱存為 theme，整份標題僅作備援 | 自訂日名經重整、預覽、套用仍保留 |
| 訪客套用收藏至新週後找不到舊週 | 單一週選單切換顯示，保留最近套用入口 | 切回原週可見原日，且儲存內容保持相同 |

獨立 reviewer 複核後，未發現上述三項日期／名稱／尋回問題的殘留原因；發布仍以主 agent 的完整檢查結果為準。

## 驗證範圍

`npm run check` 驗證 lint、224 項單元測試與正式建置。Firestore／Auth 整合測試包含 55 個案例，驗證私人收藏、同名競爭、匿名帳號遷移、日期替換、已有紀錄保護、多日公開副本和資料白名單。

`npm run test:integration` 另執行桌面／手機瀏覽器情境：手動排課 → 跨部位批次加入 → 修改組次與階段 → 重整續編 → 預覽 → 套用 → 命名收藏 → 跨週重用 → 尋回舊週 → 分享 → 接收者在獨立瀏覽器確認匯入。開啟分享連結本身不會建立課表或完成紀錄。既有自動排課、訓練紀錄、恢復調整、資料匯出與語言切換也保留相容性檢查。

公開分享目前限內建動作；私有收藏可包含自訂動作。裝置收藏不會自動覆蓋帳號收藏。詳細資料與部署約束見 [功能說明](workout-planner.md)。

## 畫面一致性修正

第一輪主要驗證功能與資料保護，並未把核准 PNG 的版面當作發布門檻；使用者指出差異後，暫停前端發布，另完成逐頁比對。

兩位 agent 獨立指出中文字重不足、手動成功訊息與調整日期占用首屏、準備組詳情常駐、挑選器多出資訊列、每日清單與底部導覽過厚，以及收藏詳情操作列仍像浮動卡片。這些問題已逐一修正。整合檢查另修正自動問卷的重複返回入口與雙層卡片，並恢復整週的日期子集分享入口。

實際畫面與核准圖、重現方式及尚未實作的原型構想見 [畫面對照](planner-ui/README.md)。準備組與休息內容移到詳情，計算、儲存、套用與訓練紀錄不因縮減資訊而省略。
