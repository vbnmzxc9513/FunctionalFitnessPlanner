# 以常用組合為起點，重新設計手動排課

版本：v5 · 2026-11-14（功能契約延續 v3；視覺已重做）。現行規格；進度以 [STATE.md](STATE.md) 為準。狀態：**正式 React 已替換工作流程，成品審查進行中，尚未上線。**

本方案回應「三個 part 要選、常用組合難找、排課痛苦」。本輪不是再加一個快捷按鈕，而是更換手動排課的操作架構。保留藍紫色系、動作資料、既有課表與安全檢核。

## 最新視覺基準

使用者否定 v3／v4 預覽的視覺品質。本輪正式 UI 改以 [reference-v5/HANDOFF.md](reference-v5/HANDOFF.md) 和同目錄 PNG 為視覺基準：日期為焦點、常用組合整合為緊湊淡紫列、動作為單面日誌、加入面板為連續清單。保留以下 UX-01～10 功能契約。

reference-v3／v4 保留作歷史與流程依據，不能當成仍合格的成品外觀。v5 的示例品牌／YL身份／側邊欄不是正式改版需求；正式全站導覽沿用實際產品。成品截圖必須另存，核對密度、對比、資料情境與操作，不把獨立原型的驗證當正式通過。

## 從任務推導畫面：第一性原理

**使用者來這裡是為了把想做的訓練放進指定日期，並在下次少做重複工作。** 他不必先學會 app 的動作分類、來源分類或儲存模型。

| 不可再拆的需求／限制 | 推導出的設計 | 必須放棄的舊做法 |
| --- | --- | --- |
| 必須知道內容排到哪一天 | 日期固定可辨識；切日保留各自草稿 | 為找組合離開當天，失去操作目的地 |
| 使用者通常已認得幾組熟悉動作 | 顯示組合名稱，可直接加入；搜尋支援肌群／部位 | 先選來源、再選階段、再逐項挑動作 |
| 他需要確認這天最後到底做什麼 | 清楚的動作清單；只有實際內容才分組 | 把空白階段畫成待完成的任務 |
| 螢幕與注意力有限 | 常態只顯示決策所需資訊；詳情就地展開 | 以說明段落彌補不清楚的控制項；把字縮小塞滿 |
| 誤操作必然發生 | 本機操作可撤銷；覆蓋前顯示影響 | 每次小操作都確認；整天覆蓋卻沒有明確差異 |
| 使用者預期點擊後立刻看到結果 | 本機加入即時，附帶同步背景處理 | 等雲端最近使用紀錄完成才改變畫面 |
| 訓練處方與完成紀錄不可失真 | 沿用資料檢核；明示未加入、重複及尚未套用 | 以簡化 UI 為由偷偷刪動作、改組次或混淆儲存狀態 |

因此主流程固定為：**日期 → 編輯這天 → 檢查／套用**。加入內容、動作詳情、收藏命名都是編輯中的局部面板，不能各自衍生成另一套排課流程。自動排課的問答產生草稿後，也應接回同一個可編輯結果。

這次允許重組容器、狀態與元件邊界。保留的是資料契約與記錄保護；舊頁面的分區、入口數量、說明文與排版都不是必須相容的產品需求。

### 每頁只服務當下決定

| 畫面 | 使用者當下的問題 | 首要內容與動作 | 延後顯示 |
| --- | --- | --- | --- |
| 日期／課表入口 | 哪幾天要排？ | 日期、每天已安排摘要；手動安排／教練幫我排 | 規劃說明、收藏管理 |
| 空白日 | 先加什麼？ | 常用組合名稱、「＋」；統一的加入入口 | 整份課表設定、階段說明 |
| 已有內容的當天 | 排了什麼，還要補什麼？ | 動作清單、緊湊的常用列、加入與檢查 | 動作教學、詳細劑量編輯 |
| 加入面板 | 找到並加入想要的內容 | 搜尋、少量篩選、組合名稱與＋；完成返回 | 展開後的內容、器材、完整組次 |
| 檢查／套用 | 哪幾天會變成什麼？ | 日期與變動摘要；套用到日期 | 詳細編排理由；無衝突時不顯示整套例外說明 |
| 操作例外 | 哪個內容沒成功，怎麼修正？ | 具體受影響項目與修正動作 | 與本次錯誤無關的通用說明 |

「大改」的完成判斷是舊的多入口流程被替換，而不是在其上增加一個更漂亮的快捷入口。每個新增常駐元素必須能回答：它幫使用者完成當下哪個決定？不能回答就移到詳情或刪除。

## 1. 實際問題與證據

檢查基準：主分支 `0563f53`。使用 390 × 844 手機視窗，在隔離的未登入本機草稿實際操作；外部請求封鎖，未動到使用者帳號。

| 現況 | 使用者承擔的負擔 | 新設計決策 |
| --- | --- | --- |
| 空白日先選「快速組合／我的收藏／從空白開始」 | 使用者先理解內容來源與流程差別，才能開始排 | 同一個單日工作區直接列出常用組合名稱；只有一個加入面板 |
| 暖身、訓練、收操三個大按鈕，加上各區的「加入動作」 | 技術上是跳轉而非必填關卡，視覺上卻像三項待完成任務 | 三階段只當有內容時出現的小標題；不用選階段才能找動作 |
| 「＋加入快速組合」看不到收藏名稱 | 使用者要記住入口，再切換到我的收藏尋找 | 收藏與內建組合在同一清單；置頂名稱直接可見 |
| 點組合只能先「查看」，再看整頁內容，最後確認加入 | 每加一個組合都離開編輯頁；連續組合要反覆往返 | 卡片直接「＋」加入，名稱列可展開；加入後面板維持開啟 |
| 加完暖身後顯示「繼續加入訓練」 | 下一步被帶往單一動作入口，不是剛才使用的組合 | 面板維持原搜尋、捲動位置；完成選擇才回到當天 |
| 收藏只以整天／階段為主要範圍 | 任意三個動作很難成為自己的常用組合 | 收藏時可勾選任意動作並命名、釘選；整天收藏仍保留 |
| `QuickWorkoutPicker.apply()` 先 await `store.markUsed()` | 附帶的雲端使用紀錄可能延遲本機加入 | 本機草稿先完成；最近使用紀錄背景更新，失敗不阻擋草稿 |

截圖：[空白日](before-empty.png)、[組合選擇](before-picker.png)、[組合預覽](before-preview.png)、[加入暖身後](before-day.png)。本次視窗中，暖身組合預覽的文件高度約 1450 px；加入後單日文件高度約 1702 px。高度不是單獨的失敗指標，關鍵是大量資訊出現在最常用操作之前。

**先前設計將「讓三階段一眼可見」當成優先驗收條件，現在應修正為「不必理解三階段也能把熟悉的組合排進一天」。** 這是設計前提的修正，不只字體或間距調整。

## 2. 使用者要完成的核心任務

預設優先情境：使用者把幾個常用組合拼成一天。若後續回覆以複用整天為主，調整首頁常用項目排序，不重新分裂入口。

> 選一天 → 點常用組合／連續加入組合 → 確認當天內容 → 套用到日期。

例：每日全身暖身 → 髖內旋 → 我的下肢肌力。暖身與髖內旋含同一個 90/90 髖轉換時，保留原組次，不重複加入或偷偷改為另一劑量。

不要求先選「暖身／主訓練／收操」，也不要求先決定「內建／自己收藏」。尚未安排收操不顯示待辦或紅色缺漏；需要檢視平衡時在檢查頁呈現實際資訊，不能宣稱每一天都必須有三段。

## 3. 頁面架構

### A. 課表入口：先看到日期與已安排內容

- 標題「我的課表」，日期範圍及每天摘要。
- 空白日期直接「安排這天」。跨日仍可多選，不強迫只排一天。
- 入口只有清楚的「手動安排」與「教練幫我排」；後者沿用互動問答，不混進手動頁的三種來源選擇。
- 既有課表點入可修改；不要每次重走日期設定。
- 日期匯入、分享、套用收藏等結果進同一份可編輯草稿，而非另建一套編輯畫面。

### B. 單日工作區：內容與常用組合

由上到下：

1. 日期、草稿狀態、時間上限／器材摘要（點摘要才調整）。
2. **常用組合名稱直接列出**：使用者釘選優先，接最近使用；預設最多 3 筆，附「查看全部」。初次使用沒有收藏時，展示每日全身暖身與相關內建組合，不留空白分類。
3. 「動作」：一列一個動作，僅名稱、簡短組次；有內容才出現暖身／訓練／收操小標。八段暖身必須呈現為八個獨立動作。
4. 點動作即可看詳情與編輯，長按可作快捷方式，不能成為唯一入口。排序提供按鈕，不能只靠拖曳。
5. 固定底部：「＋加入」與「檢查課表」。不能被手機鍵盤、安全區或底部導覽遮住。

課表命名、收藏、複製、分享放「更多」；收藏成功後，組合名稱立即出現在常用區，無須再到別頁找。正式課表的儲存／待同步／失敗狀態與本機草稿分開，不能模糊成一個「已儲存」。

### C. 唯一加入面板：連續挑選，不反覆跳頁

- 手機用全高面板；桌面側欄。頂端一直說明加入哪一天。
- 預設「組合」，另一個選項是「單一動作」。這兩類是不同大小的內容，不是三個必填步驟。
- 同一搜尋框支援名稱、部位、目的與自訂標籤；部位快捷篩選最多顯示數個，其餘開篩選器。篩選保留於本次編輯，不在每次加入後清空。
- 我的釘選／最近使用先列、內建接著列。沒有我的收藏就不顯示空段落；不另外要求切換「我的／官方」頁籤。
- 搜尋結果以符合程度呈現；來源由區塊標題或展開內容交代，不在每張卡片重複。不要讓大量收藏遮住更符合的內建搜尋結果。
- 卡片預設只顯示名稱、動作數與「＋」。點名稱列／箭頭展開動作、組次、估時及器材；不預先堆疊來源、用途說明與動作摘要。加入按鈕提供完整讀屏名稱與實際新增數。器材不符等會影響能否加入的例外仍直接標明，不能藏在詳情。
- 多次加入後留在原面板、原捲動位置；底部在操作後顯示本次結果與「完成」。加入不等於套用正式日期。
- 單一動作也可直接加入；預設沿用動作／組合本身的階段，在詳情修改。不先問使用者要加到哪一 part。
- 確認八個動作各自有劑量，不能改回一個「八段伸展」標題項目。

### D. 收藏、整天套用及分享

- 「收藏成組合」：勾選動作 → 命名 → 收藏並釘選。可跨暖身／訓練／收操選取。
- 只收藏不變更正式日期；保留快照、動作 ID、組次、相對順序與來源。
- 整天收藏在清單明示「整天」。主要動作仍是加入內容；「取代這天」為明確次要動作，先列出會刪除及保留的內容再確認。
- 分享已排課表／收藏沿用現有分享資料格式；收件者匯入時選套用日期並預覽映射。不可把 A 的 3 天課表無提示地覆蓋 B 的 5 天課表。
- 本輪不重寫分享服務、自動排課引擎或新增社群首頁。

## 文字減量修訂（使用者追加回饋）

第一版原型仍然需要閱讀太多說明；本修訂取代先前「卡片同時展示大量摘要」的設計。

- 預設畫面不放操作教學段落；按鈕、選取狀態與位置本身需說明操作。
- 每個組合只用名稱與一行動作數；完整名稱保留，不縮成難懂代碼，也不靠縮小字體塞資訊。
- 移除重複來源標籤、前兩個動作摘要、「可連續加入」及「點動作可調整」等常駐文字。
- 無操作時不放提示；加入、重複、失敗時才顯示簡短且具體的結果。
- 「＋」具有至少 44 px 觸控區及完整讀屏名稱；名稱列用箭頭表示可展開，不能只靠長按。
- 390 × 844 的預設組合面板可完整顯示目前示例的五個組合；詳情與個別組次仍可展開查閱。
- 驗收包含完整名稱、例外與錯誤訊息可理解；不能為了少字隱藏覆蓋、未加入或未儲存等重要事實。

## 4. 直接加入與例外處理的邊界

| 情境 | 行為 |
| --- | --- |
| 可用、未重複且在限制內 | 一次點擊加入草稿，立即顯示實際新增數、可撤銷 |
| 部分重複 | 預設保留已存在的劑量和階段；按鈕的無障礙名稱及操作回饋顯示真正新增數；提示「新增 2，1 個重複保留原設定」，可查看差異 |
| 全部已存在 | 顯示「已在課表」，不能讓使用者一直點卻沒有結果；劑量差異仍可進內容查看與明確選擇更新 |
| 器材、治療／經驗／搭檔限制不符 | 不先寫入候選內容；顯示具體受影響動作與解決方法，不能把健康限制當成一般可略過警告 |
| 超時或超過每日動作上限 | 顯示差多少與本次變動，不自動刪減。可調整劑量、移除所選內容或改時間，再重新檢核 |
| 使用者選擇只加入部分 | 列明保留與排除內容，再確認；不能只顯示加入成功掩蓋未加入項 |
| 替換整天／階段 | 明確列出移除清單，確認後才變動；有完成紀錄的日期沿用保護規則 |
| 連續加入後撤銷 | 僅撤銷最近一次本機操作，不抹掉其他日期或後來編輯；每次編輯更新操作歷史，不能恢復過期快照 |
| 剛改帳號或日期 | 查驗操作的帳號與日期；舊請求完成不能寫入新目的地 |
| 離線／雲端失敗 | 本機草稿可繼續，標明未同步；正式套用失敗可重試，不宣稱已存入帳號 |

現有 `previewQuickWorkout` / `applyQuickWorkout` 已提供大部分核心檢核。不能為了「一鍵」另寫一套忽略限制的快加函式。

「髖內旋」與「髖外旋」不可互相冒充。目前內建資料有髖內旋、足弓、肩胛上旋、每日暖身四組；髖外旋若另增內建，需先確認動作內容、標籤及劑量，不以改名字充數。

## 5. 評估依據與驗收

- Nielsen Norman Group，[Recognition over Recall](https://www.nngroup.com/articles/recognition-and-recall/)：讓名稱與選項可辨識，不靠記得藏在哪裡。對應常用組合直接可見、保留搜尋上下文。
- Nielsen Norman Group，[Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)：常用動作放前面，低頻設定延後。不能反過來把組合藏起來、卻把所有限制說明放第一屏。
- Nielsen Norman Group，[Usability Testing 101](https://www.nngroup.com/articles/usability-testing-101/)：讓代表性使用者完成具體任務，觀察完成率、錯誤與困難。程式自動操作／專家走查不能當成真人可用性證據。

以下數值是**本案待驗證的產品目標**，不是引用文獻的通用標準：

| 驗收任務（不提示入口） | 目標與觀察 |
| --- | --- |
| 找到自己的常用組合 | 首屏至少看得到一個已釘選的名稱；5 位代表使用者至少 4 位在 10 秒內找到 |
| 從當天空白頁加入兩組內建組合 | 常規路徑 ≤4 次點擊（開面板、加 A、加 B、完成）；不要求選階段或開詳情 |
| 加八個暖身與髖內旋組 | 共 10 個不重複動作，90/90 原組次與階段保留；使用者能說出為何不是 11 個 |
| 收藏三個自選動作，再找到它 | 不用離開排課；命名成功即出現於常用區；重新開啟仍找得到 |
| 加錯一組並恢復 | 能撤銷，原課表及其他日期不受影響；不需要整份重排 |
| 處理超時／器材不足 | 知道哪裡不符合、如何修改；不能把未加入誤認成已加入 |
| 完成後知道存在哪裡 | 能分辨草稿、正式日期課表及收藏；不把收藏誤認為排課已套用 |
| 互動回饋 | 本機點擊視覺回饋目標 p95 <100 ms，使用者手機 CPU 節流後量測；不可把 headless 測量冒充實機成績 |

正式真人測試建議涵蓋：新使用者、熟悉現有 app 的使用者、習慣以組合排課者；以同樣任務比較舊版與新版，交錯測試順序以降低熟悉效應。記錄完成時間、求助次數、誤操作及每題 1–7 分難易評分；小樣本結果只做改善方向，不宣稱統計代表性。

## 6. 原型與實際驗證範圍

[開啟互動原型](prototype.html)。自含 HTML，可離線打開；只使用獨立的 prototype localStorage key，沒有 Firebase／正式課表寫入。

原型使用現有四組內建內容，另有明確的個人收藏示例。支援直接加入、連續加入、重複保留、撤銷、單一動作搜尋、任意子集命名收藏、重新開啟及編輯操作。展示 390 px 手機與 1440 px 桌面版，並驗證 320 px 無橫向溢出。

原型不含完整動作庫、真實器材／健康檢核、時間估算、帳號同步、跨日操作或正式套用；不能拿它開實際訓練處方。上述功能屬正式實作驗收，而非原型已完成項。

重現方式：先執行 `node scripts/smoke-server.mjs 5211`，再執行 `node scripts/combo-first-prototype-review.mjs`；舊版截圖使用 `node scripts/combo-first-current-audit.mjs`。腳本使用本機 `/usr/bin/chromium`。

驗證記錄見 [prototype-review.json](prototype-review.json)。這是自動化原型走查，**沒有宣稱真人或 sub-agent 使用者測試通過**。

## 7. 實作順序及維護界線

1. 先用本原型確定單日工作區、加入面板與收藏流程。實作前固定三個關鍵畫面：空白日、加入組合、已有內容的當天。
2. 將 `ManualPlanner` 的入口狀態收斂成 dates → editor → review；picker 是 editor 上的局部面板，不是替換整頁的工作流。保留 draftStorage 的隔離範圍。
3. 把 `QuickWorkoutPicker` 拆成可重用的組合列與例外預覽，並整合 `BatchExercisePicker` 搜尋。`SessionPlanEditor` 移除三個大階段入口、空階段區塊和重複加入按鈕。
4. 共用 domain preview / apply / undo，以及既有劑量驗證、過期快照與正式日期保護。`markUsed` 背景更新；資料失敗不阻塞本機操作，避免舊請求污染帳號。
5. 收藏支援動作子集並接現有 snapshot 格式；釘選／最近使用同步沿用 store，不新增另一個「快速課表」資料庫。
6. 對照原型進行手機／桌面實際截圖審查及任務測試；驗收包含：英中語系、鍵盤／焦點／讀屏、重複、無結果、超時、離線、帳號切換、已完成日保護、分享匯入與八個暖身獨立記錄。
7. 小範圍試用後發佈；先保留可回復的 UI 切換方式，穩定後移除舊入口。不能長期把新版疊加在舊版旁邊，形成第四種模式。

**本輪排除**：重新設計全站、改色系、改完成紀錄機制、重新訓練自動排課引擎、分享格式遷移、增加新的排課模式。將變動集中在「快速組合排一天」，避免再次邊做邊擴張。

### 上線前的證據規則

- 實作完成後先跑受影響的 domain／UI／emulator 測試，再執行 `npm run check` 與相應整合套件。功能或資料阻斷問題修好前不宣告完成。
- 截圖必須來自正式 React 路徑，放入獨立的 implementation-review 目錄，附 commit、視窗、語系及資料情境。prototype-review.json 只能證明原型。
- 對照採「空白日／已有內容／連續加入／收藏／例外／套用結果」，不只挑最漂亮的組合面板。檢查版面之外，要記錄操作次數及使用者可能誤解的狀態。
- `reference-v3/` 是保留的設計證據；目前涵蓋單日、加入與收藏，**不代表日期、多日、例外、套用頁已設計驗收完成**。缺少的狀態在 P1 補足。
- 真人測試及實機測量未取得時標記「未驗證」，不可把模型模擬或 headless 結果算成真人通過。內部審查與真人回饋分開，不虛構品質保證。
- 發佈後確認服務版本與主要任務，再標記已上線；資料相容下保留可回復版本。沒有驗證就不填 PASS。
