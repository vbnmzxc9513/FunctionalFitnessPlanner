# 訓練回饋功能 review

四位 sub-agent 分別實作規則、資料保存、訓練畫面及 App 串接，主 agent 審查跨模組契約、修正邊界並驗證發布。實作順序見 [計畫](coaching-upgrade-plan.md)，操作見 [流程](coaching-loop.md)。

## 審查後修正

- 補做其他星期的課表使用實際日期，同一日期不算兩次進階證據；今日不能預先填明日反應。整合測試使用昨天作為實際日期，避免週一執行時錯把當天當成可追蹤的翌日。
- 進階只使用最近 28 天兩筆可比較紀錄，逐組／逐側達標；缺 RIR、品質、翌日反應、臨床狀態或阻力定義就不加量。徒手變式與纜繩機台／設定也要明確且一致，不能只比較重量片數字。
- 當日調整不增加新動作、工作量或縮短休息。已完成的處方與歷史快照保留，版本或完成旗標改變會使預覽失效。
- 公開草稿採獨立原課表與安全子集驗證，保留完成主項後停止未完成暖身的歷史；沒有放寬 AI 課表驗證。取消旗標若會使草稿非法，先保留資料並提示重新排課。
- 預覽轉存同時保存課表、完成紀錄與私人資料；轉存未完成時阻擋競爭寫入。UID 切換重新訂閱，不顯示前一帳號資料。
- Firestore 驗證完整五組雙側紀錄及更新仍在規則運算預算內；測試 40 筆預覽紀錄一起原子保存。歷史查詢優先載入較近的週。
- 舊課表的精確名稱與別名可保存 canonical ID 實際紀錄，不使用部分字串猜測。
- 載入雲端紀錄後才建立表單；遠端更新可同步未編輯表單，保留未儲存輸入。切語系與完成勾選不清空表單，遠端翌日反應不被舊表單默認覆蓋。
- 分享仍只含白名單動作與處方，私人阻力說明、症狀、RIR、每日狀態與紀錄不加入分享。

## 驗證

- `npm run check`：ESLint、78 項單元測試與正式 build 通過。
- 原有 17 項 Firestore 整合測試與新增 12 項訓練整合測試通過；新增的舊課表／調整後採用案例另以模擬器重測。
- 原有桌機／手機流程與新增桌機／手機訓練回饋流程通過，包括預覽、重整、分享、實際日期、翌日回報、登入採用、雲端載入、語系切換與保留已完成處方。
- 選配 AI 後端的共享 bundle 建置及 import 檢查通過；本輪回饋規則在本機執行。

數值門檻是保守編排規則，仍須個人訓練與治療判斷。影片教學、完整 4–8 週成效評估及自動套用負荷進階不在本輪範圍。每週同一動作格只保留一筆可訂正紀錄；免登入資料為分頁暫存，正式帳號近期載入範圍為 12 週。
