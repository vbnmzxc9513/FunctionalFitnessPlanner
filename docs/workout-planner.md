# 手動排課、收藏與分享

「課表」的本週首頁提供排課入口與七日安排：

- **手動排課**：選擇最多跨 28 天的日期，可不連續；每天先看暖身、訓練、收操三區。六個原始階段、準備組及劑量保留在編輯與詳情。加入動作時可依類型、部位和名稱搜尋，跨篩選保留多選，按「加入」才放進草稿。
- **自動排課**：沿用日期問卷與固定規則引擎，預覽後確認套用。
- **我的收藏課表**：從每日內容將當天命名收藏；可預覽、改名、移除、分享及指定新日期套用。收藏保存獨立副本，原課表後續變更不會修改收藏。

週切換顯示所選週的七天；空白日期標示「未安排」，不憑空新增休息課表。每日與整週均有分享入口，整週分享可再選日期子集。規劃條件、部位平衡與手選採用明細放在列表後展開；手機先看清楚這週排了什麼。

每次手動、收藏或分享匯入都會先選目的日期，再檢查新增／替換內容。已開始、勾選完成或有訓練紀錄的日期不能覆蓋；尚未開始的課表須逐日明確同意替換。中間未選的日期不會自動補成休息日。套用只建立計畫，不代表已完成訓練。

## 資料

- `domain/manualPlanner.js`：日期草稿、標籤篩選、批次加入、階段／順序／劑量驗證。每日本體最多 8 個動作；八段全身拉伸流程計一個動作，時間全部納入。準備組附屬於主項。
- `domain/planAssignments.js`、`ApplyWorkoutPlan`：共用日期映射、預覽與衝突同意。雲端透過 `periodRepository` 交易再次檢查；裝置套用前檢查儲存狀態並先完成持久化。
- `workoutTemplates`：帳號私有命名收藏。只保存動作、組次、順序與必要動作名稱，不帶來源日期、健康資訊、實際重量、完成紀錄或私人筆記。`workoutNames` 交易索引防止同名；改名須符合 revision。
- 登入帳號（含匿名帳號）使用雲端；未登入使用裝置儲存。裝置收藏不會自動覆蓋登入帳號收藏。匿名帳號升級至既有 Google 帳號時，收藏以可重試方式匯入，同名追加編號並告知使用者。
- 非連續日期規劃的 `planningPeriods.dates` 保留實際選取日期；舊資料缺少此欄時仍讀取原完整期間。

## 分享

新分享支援 1–28 天，保存相對天數間隔。接收者不必登入就能預覽；匯入時選新起始日保留間隔，或逐天指定日期。匯入為獨立副本。

登入者建立 `#plan=<id>` 短連結；未登入建立有長度上限的 `#program=<payload>` 連結。較長分享須登入後建立短連結。既有 `#workout=` 單日連結保留相容。

公開副本僅包含使用者確認的公開名稱、內建動作、組次、順序、相對間隔，不含來源日期、帳號 UID、健康資訊或實際紀錄。公開根目錄禁止列舉；作者識別登記另存私有集合。每份分享不可變更，目前不提供撤回；建立前會明示。

自訂動作可私有收藏；公開分享目前限內建動作。遇到不支援的動作會阻止整份分享並說明，不會默默略過。收藏中的自訂動作若已從自己的動作庫刪除，須先還原才能套用。

## 驗證與部署

`npm run check` 執行 lint、單元測試、正式建置。`npm run test:integration` 執行 Auth／Firestore 模擬器、權限與交易測試，以及桌面／手機瀏覽器操作。新增測試涵蓋日期間隔、明確替換、紀錄保護、命名唯一性、匿名升級、公開資料白名單和完整匯入流程。

發布前須先將此版本 `firestore.rules` 部署至目標 Firebase 專案，再發布前端。GitHub Pages 工作流程不會自動部署 Firestore 規則。
