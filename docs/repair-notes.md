# 非 Gemini API 修正

本次把 App 的 UI 與 Firebase／domain 邏輯拆成可測試模組，保留原有 Gemini request 行為。

## 已修正

- 桌機與手機使用同一份課表增刪／保存／取消控制。
- 使用 UID 與 ISO 週作為 session key；換帳號、登出、跨週會重建草稿與畫面資料。
- Firestore 難度即時訂閱；每週反饋以固定基準重算，重複選擇不會累加。
- 課表與統計快照原子保存；revision 防止舊草稿覆寫；完成紀錄保留為歷史。
- 雲端儲存上一份課表，重新整理後仍可復原，包含最初的預設課表。
- 完成動作以單欄位 transaction 寫入，避免完整 map 覆寫其他裝置的進度。
- 實際完成日期與類別快照、週末熱圖、真實課表分母、按日期歸月份及月份排序。
- 完成率與畫面共同使用標準動作代碼；移除不可靠的 substring fallback。
- 預設課表排除停用／刪除動作，空白日顯示休息；零啟用動作阻擋排課操作。
- 測量數值與日期驗證、依日期回填、部分更新不清空舊值。
- 共用介面、單位、錯誤訊息與月份完整雙語；既有 AI／使用者產生的內容保留原語言。
- 可覆寫 Firebase Web config 與本機模擬器模式；資料訂閱限量並可載入更早紀錄。
- 訪客綁定 Google 保留紀錄；已存在帳號的匯入可重試且保留原帳號資料。
- 訂閱與操作錯誤顯示、卸載時取消訂閱、使用者身分檢查、正式畫面移除 stack trace。
- 本機金鑰清除與資料送往 Gemini 的說明。
- 穩定版 Vite、lazy loading、拆分 Firebase／圖表／Markdown、統一部署 metadata。
- 清除範本與診斷檔案，修復 lint，加入單元、rules／交易與瀏覽器測試及 CI gate。

## 相容性與部署

舊 progress／plan 資料可繼續讀取；新版只在使用者操作時補上日期、類別與當週課表快照，不執行大規模歷史資料遷移。刪掉的舊 completion 已無法由現有資料還原。

月完成率表示目前已載入週紀錄的排定任務完成比例；總完成數保留被移出課表的已完成工作，兩者可能不同。舊紀錄沒有實際完成日期時使用排定日期。

Firestore rules 需要另行部署到 Firebase；git push／Pages 工作流程只會發布前端。Google Auth 授權網域及 OAuth popup 的正式帳號設定沒有在此環境驗證。

## 排除範圍

Gemini 模型選擇的實際呼叫、prompt／schema、回應驗證、微調上下文、HTTP timeout／retry，以及 AI 生成內容的翻譯或處方時長，均未在這次更動。Firestore 的資料交易與畫面容錯屬通用應用層修正。

## 驗證

- lint 與 production build 通過。
- 10 個單元測試通過：日期、反饋、統計、歷史相容性、測量驗證、語言鍵值一致性。
- 12 個 Firebase Emulator 整合測試通過：資料隔離、rules、查詢、並行寫入、原子保存、復原、部分更新、guest 匯入與身分切換。
- 桌機 1280×900、手機 390×844 的完整流程通過：訪客登入、打卡、增刪課表、保存／重新整理／復原、反饋、數據、跨週、登出、英文。
- Gemini 生成函式與原始版本比較一致（僅搬移、增加 export 及整理空白）；沒有對正式 Gemini 或 Firebase 寫入。
