# 本週選課與確認預覽

2026-10-16。沿用今天／課表／紀錄與藍紫色系，把每週排課整理成三步問卷及一頁預覽。

## 使用流程

1. **目標與時間**：選主要能力方向、最多兩個重點部位；確認球日、時間、器材與經驗。比賽、球量與自由文字目標收在選填設定。
2. **身體感受**：分別勾選無痛緊繃與運動後仍痠的區域，各最多兩項。疼痛、治療與活動限制另填，優先於偏好；不由痠或緊推斷診斷。
3. **挑選動作**：推薦每批四項，可換一批或搜尋；主要訓練、暖身、收操各有用途篩選。推薦僅從有完整資料且符合當前條件的動作挑選，按目標、部位與常用排序。可選最多八項，也可不選，交給模板搭配。
4. **預覽與確認**：先顯示候選實際排入數量，再看七日安排、覆蓋與每個候選的結果。點一天可看唯讀完整內容；返回修改保留選擇。按「確認套用本週」才修改正式課表。

動作庫中的「選進本週」與「檢視候選並排本週」通往同一套流程。長期常用收藏與本週候選互不修改；未登入仍能選本週候選與免費預覽。套用後週總覽持續顯示保存的候選及當前課表的實際排入日，未套用的新選擇另有提示。

## 排課與回饋

- 選擇是偏好，不是必排指令。免費模板在一般、無限制、非恢復優先與非賽前／賽後的訓練日，替換同目的的既有槽位。蹲／弓步、髖伸展、推、拉、核心各保留目的；不為候選另加訓練日或槽位。
- 一般升溫不被候選取代；主要肌力的輕準備組按實際第一個主項、器材與左右側重新建立。候選採起步處方及原槽位較保守的組次，不自動加重，也不縮短原有或候選需要的休息。
- 重新計算雙側、準備與休息時間；不足時刪減工作，仍守每日時間上限、八項上限與跳躍驗證。可優先保留候選，但不優先於必要的升溫或恢復守門。
- 自述運動後肌肉痠採恢復優先、較少肌力日與正式組。無痛僵硬只影響舒適活動搭配；疼痛、未確認限制、球日與比賽守門照既有規則優先。
- 預覽結果由實際 `routine` 推導，區分已排入、不可用、器材、經驗、搭檔、健康限制、比賽、恢復與時間／同目的槽位未容納。AI 未採用而無法確定原因時使用中性說明，並保留其排課說明，不捏造確切原因。
- BYOK prompt 加入候選與肌肉痠的處理；候選不擴張可用動作清單。返回與切換畫面不自動重送 AI 請求。

## 資料與保存

- `weeklyIntent.weeklyExerciseIds` 為可選欄位，最多八個不重複、長度 1–100 的 ID；舊快照形狀不變。Firestore 規則逐項驗證，仍以兩份每日鏡像確認整週原子寫入。
- 肌肉痠 `sorenessRegions` 放在規劃 context，沒有加入週意圖或分享白名單；既有健康備註、實做與分享邏輯沿用。
- 未套用問卷用 sessionStorage 依帳號與週次隔離；同週重新整理可以繼續，儲存受限時顯示提示。套用後偏好依原帳號保存在本機，正式週快照保存在帳號或未登入的本分頁預覽。
- 進入新週清空候選與本週肌肉痠回報，保留長期收藏、器材及既有健康限制；若已有新週保存快照，依該週快照還原候選。不同帳號不自動沿用未套用草稿。
- 預覽記住週次、帳號、條件、模式、語言、可用動作、課表版本與完成事實。資料變動後停用套用，要求重新預覽；寫入時再以交易核對版本與完成旗標。
- 預覽不寫正式課表、完成旗標或實做，也沒有可填的實做表單。確認後保留原有私人實做與符合新課表的預覽完成標記。訪客採用仍為原子操作。

部署需先更新 `firestore.rules` 再發布前端；不需搬移舊資料。App AI 體驗維持關閉，不部署付費 functions。
