# 推廣功能實作計畫

目標是讓球友先取得可執行的羽球體能課表，再選擇保存、分享或 AI 微調。自備 Gemini 金鑰保留為進階功能。

## 1. 無金鑰排課

- 用現有動作庫、器材篩選、球日與時間預算建立可重現的規則式課表。
- 每日列出暖身、主項準備組、協調／步伐、肌力、輔助與收尾；恢復及休息允許短課或零動作。
- 球量、連續球日、比賽日期、先前反饋及活動限制優先於湊滿時間。
- 驗收：二四六等不同球日、二四五／二五六、不同器材、5–40 分鐘、限制與減量皆通過現有課表驗證；不發出 AI API 請求。

## 2. 首次使用流程

- 第一次先填球日、時間、器材及目標；進階條件可展開。
- 未登入可取得與預覽課表，登入／訪客保存時採用這份課表；既有帳號不自動覆寫已保存內容。
- 免費排課為預設；自備金鑰與 App AI 體驗有明確選項和可用狀態。
- 先用本機匿名計數觀察首次排課、首次完成與跨週回訪。此版本不收集遠端分析資料，不能當作全站轉換率。
- 驗收：手機／電腦、免登入排課、登入後採用、取消、重整、登出與帳號切換皆不丟失或串用私人資料。

## 3. 安全分享

- 提供每日課表圖片與公開可讀的分享連結。
- 分享只允許動作庫的 ID、階段、組次與休息；不包含治療說明、私人筆記、身體資料、帳號、完成紀錄或金鑰。
- 不公開自訂名稱與自由文字；連結讀取驗證大小、格式、階段與劑量，不直接採用不可信資料。
- 驗收：分享可免登入開啟，中文不損壞，無效連結有提示，私密欄位及惡意輸入測試通過。

## 4. 少量 AI 體驗

- 使用 Firebase callable 後端、Secret Manager、登入驗證與 App Check。
- 每個非訪客帳號每 ISO 週最多一次嘗試；全站每日額度、固定模型、輸出上限及停用開關由後端控制。
- 後端自行建構候選動作與 prompt、驗證生成結果；並行請求和重複請求不重複花費。
- 預設關閉。正式啟用需要專案專用 Gemini 金鑰、Firebase 計費／部署條件、App Check 設定與營運者指定的額度。呼叫次數限制不等於保證每月金額。
- 驗收：未登入、訪客、未啟用、超額與並行請求皆拒絕或返回已有結果；金鑰不進前端或 repository，錯誤不假裝成功。

## 分工與 review

Sub-agents 分別實作排課、使用流程、分享與 AI 後端；主 agent 審查邊界、安全、醫療限制、舊課表相容性及行動版操作，再整合。

完成後執行 lint、單元測試、Firestore 模擬器、手機／電腦瀏覽器與 production build。推送 GitHub，必要時部署規則，確認 Pages 實際版本。未具備設定的 AI 體驗維持關閉，並在交付文件列明啟用步驟。
