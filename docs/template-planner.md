# 免金鑰羽球課表

`src/domain/templatePlanner.js` 的 `generateTemplatePlan(exercises, context, dailyTime, lang, options)` 在瀏覽器依固定規則產生課表，不呼叫 AI API、不傳送健康備註給外部模型，也不需要金鑰。回傳結構與 AI 課表相同，最後使用 `validateGeneratedPlan` 驗證。

## 排課規則

- 每週一至五共五個槽位，週末球日也納入負荷。球日午休以輕活動恢復為主。
- 每週最多兩堂主要肌力，至少隔一個非肌力日。疲勞回報、三場球且有連續球日或高球量時，最多一堂；明確每場不超過60分鐘的light球局不僅因連續日永久限一堂。明確高強度球局前一天不加主要肌力；球局達 120 分鐘只會減少肌力劑量／堂數，不自動當成高強度而封鎖所有非球日。
- 以互補模式選擇已啟用的基礎動作，推拉器材允許時同堂保留低量推拉；少數蹲／單腳槽依日曆週A/B輪替。穩定重點用單腳髖鉸鏈搭配蹲／弓步，不重複兩個髖鉸鏈；提供肌力、穩定、協調、均衡四種重點，不隨機換動作。自訂動作不納入模板。
- 尊重器材、搭檔、進階動作與肩部限制篩選。獨自預設方向步序不被描述成未知訊號反應。
- 日內依暖身、短協調、主要肌力、輔助、選配收尾排列。各首次出現的主要肌力模式附同動作輕準備組，其後30秒休息也計時。
- 一般無限制的訓練日與球日恢復，30分鐘以上直接用A13（10分鐘八段動態拉伸），不排A01、跑步、快走或側移暖身；10–29分鐘或A13停用時採A12（6分鐘八段精簡流程），兩套擇一。全部左右側與內部轉換已計時，估時另留轉場。
- A13 保留使用者的八段順序：動態嬰兒式後坐、偉大拉伸＋側向移重、貓牛式、徒手 Y/T、前鋸肌牆推、胸椎開書、90/90 髖轉換、大小腿動態活動。各段分配 50／120／50／60／50／70／70／130 秒。明確涵蓋胸椎、肩胛控制、髖前側、內收肌、髖內外旋、股四頭肌、腿後側及直膝／屈膝小腿活動。每段慢速進出，不久停、不彈震、不拉痛、不趕次數。
- 每日清單只顯示一項暖身流程，長按或點「詳細／記錄」才展開八段；全套完成才勾選一次。準備組仍獨立計時，不能用暖身取代。A12 的歷史處方與六分鐘說明保持原樣，重新排課才採用新預設。
- A12／A13 都視為肩部負荷流程：治療限制或健康狀態未確認時排除。球日恢復可保留整套；輕疲勞先減正式主項及額外步序，不能只砍暖身。純休息與限制未確認時不強塞，賽前只能保留歷史熟悉或warmupFamiliar明確確認的流程，這個確認不放行任何新肌力或治療限制。短課採精簡候選；已安排完整流程時先減其他工作，不刪暖身來塞更多肌力，也不壓縮成兩分鐘或數次。固定八段開場不被單項偏好或跑步取代；未採用的單項暖身在報告標示warmup_flow，不疊加兩套。
- 動態活動準備當天主訓練；較長靜態拉伸可放收操，按感受選擇。活動度涵蓋不等同療效，不能保證解除沾黏、治療不適或預防傷害，不要求每天平均拉遍所有肌群。
- 每天最多八項。時間包含左右側、正式組休息、準備組和換動作；不足時先刪低優先工作，再減正式組數，不縮短必要休息。
- 比賽距離以課表每一天的日期計算；最後十天減量、前兩天及比賽日休息、賽後先恢復。賽前訓練僅沿用 `options.previousPlan` 出現過的動作；沒有歷史時只安排恢復。先前課表並不證明已熟悉，使用者仍須確認。

## 依負荷與間隔安排活動度

`src/domain/mobility.js` 統一八區活動度分類、歷史摘要、區域優先與短動態槽替換。`generateTemplatePlan` 的 `options.logs / progressByWeek / readiness / previousSessions`（重排整週時可另用 `mobilitySessions` 提供區域歷史，避免把將重排的未完成日誤當固定肌力日）、`generatePeriodPlan` 的同名選項參與排課；日期工作區同時使用已載入歷史與本次載入的帳號紀錄，並納入預覽指紋。

- 一般課直接保留 A13／A12，已包含的區域不重複疊加，原有選配呼吸收尾槽可換成一項動態暖身重點。使用者明選的收尾保留，沒有收尾時明說可省略；不延長時間或增加超過八項。
- 正常球日／恢復日採同套舒適八段拉伸；短課或痠痛影響活動時改一至兩項允許區域的活動，最多三項工作；不是額外的高強度訓練或整套暖身。純休息不加動作。
- 近兩天的蹲／弓步、髖鉸鏈、推拉、步伐與球日影響活動度重點；同時按滾動七天的已知安排與間隔輪替，不以肌力有沒有練到該區作唯一依據。每區約兩個舒適活動日是起步參考，非醫療最低門檻，也不強迫補課。
- 只有有效實做紀錄且至少一側有實際活動，或有有效 `completedAt` 日期的完成標記，才建立已做證據。舊計畫沒有完成證據時不抵扣活動度維護；近期計畫只能作條件式負荷參考。尚未到來但早於目標日的課表可作預期分布，後於目標日的課表不能提前抵扣。
- 每一天按日期順序累積本週安排，跨週保留前段資訊，不在星期一重置區域間隔。完成／有紀錄的日期與歷史處方保持原樣。
- 狀態回報的昨日球量可覆蓋週曆假設；未知資料維持未知。實做紀錄回報近期症狀惡化時暫不開立額外體能或針對性拉伸，先確認可用活動。
- 暖身註解列出當天區域與原因，實做、回報與預定分開。八區展開面板只呈現安排日期，不宣稱已完成、實測活動度、身體失衡或受傷風險分數。肌力、滾筒與肩胛啟動不自動算拉伸。

A14 是扶穩交替屈膝動態活動，A15 是坐姿 90/90 髖轉換；兩者可獨立填入短暖身／恢復槽，避免沒有完整流程的週一直漏掉大腿前側與髖旋轉。所有新增動態活動仍套用器材、啟用與肩部限制。

## 回饋與限制

本週選課以 `context.weeklyExerciseIds` 參與同目的槽位替換，不新增槽位；`context.sorenessRegions` 使本週採恢復優先。候選、時間取捨、準備組與預覽確認規則見 [本週選課](weekly-selection.md)。

`options.focus`（亦接受 `goalFocus`）為 `balanced`、`strength`、`stability`、`coordination`。`lastWeekFeedback=-1` 或未確認的疲勞備註減少劑量；「太簡單」不會自動加重。自由文字目標不被當成程式指令，也不聲稱已完整解讀；更複雜的需求應由教練確認或使用 AI 方案。

一般健康備註只接受明確「沒有疼痛／沒有受傷」等簡短否定。模板無法理解的非肩部限制、未指明的健康限制或新麻木／無力回報，產生完整休息課表。肩部治療限制不明時保持休息，不用走路替代，也不自動安排含抬手或支撐的八段流程；不以無痛或日期自動放行。這是保守模板，並不做診斷。

無器材時可安排徒手下肢與可用的上肢動作，不發明拉力器材。不會為了填滿時間加入高強度循環。動作劑量、階段時間與候選 ID 都通過既有驗證器，但這些檢查不構成醫療安全保證。

單元測試包含球日與週末、5–40 分鐘、器材組合、搭檔、停用動作、健康限制、疲勞／負荷與比賽日期矩陣，並檢查固定輸出、輸入不被修改，以及與 AI 課表 schema 的相容性。

既有已儲存課表不會自動覆寫；在「調整本週目標」重新產生預覽後，確認套用才更新。AI prompt 使用相同起手式與例外；生成與公開分享驗證拒絕縮時／重複劑量。沿用既有處方格式，不需 Firestore 規則或資料遷移。

一般暖身的參考：[NHS 暖身指引](https://www.nhs.uk/live-well/exercise/how-to-warm-up-before-exercising/) 建議先漸進活動。此處八段組合是本產品的教練編排，並非該指引的指定處方或治療方案。

## 恢復週與摘要回歸修正

- 2026-10-19–23、球日二三五、每場 120 分鐘、一般混合強度且有疲勞備註，仍可在非球日保留一堂低量肌力；健康／症狀／比賽限制優先。若實際設定為高強度且沒有合適肌力日，允許整段恢復，並明確解釋高強度球局與減量原因。
- 疲勞不再整週停用活動度輪替。無健康限制時保留八段拉伸。sorenessImpact=mild只代表輕痠無痛、不影響動作；limited或unknown且有痠部位時不安排正式肌力或整套受影響流程，僅安排其他允許區域的精簡活動，不超時、不當成治療。
- 雲端日期摘要只有 bounded weeklyIntent，沒有器材與健康備註。相同 periodId 優先保留本機完整問卷，避免較晚解析的 server timestamp 使器材欄位消失；只有雲端摘要時標示條件未保留，不能假設徒手或沒有啞鈴。選課報告以該份課表條件判讀，零肌力明說零肌力。
- 問卷最後一步與日期預覽顯示器材；只有恢復／休息的預覽顯示原因，仍由原有套用流程決定是否採用。歷史課表和實做紀錄不自動改寫。

## 2026-10-19 教練複核修正

- `recoveryState`為unknown／normal／reduce／recover，備註只補充；明確的「沒有疲勞」「睡得很好，沒有疲勞」不觸發減量，未知文字不一律當疲勞。舊備註仍可辨識明確睡眠不足／有點累。當日readiness與臨床限制優先。
- reduced工作先取消額外步序／核心並減少正式下肢主項，保留指定拉伸；recover不排正式工作。四週正常一堂週仍應有可用推拉、蹲／弓步與髖鉸鏈，保持基礎動作可追蹤。
- A12／A13的肩部安排指流程中的主動肩部活動與控制，不等同被動拉伸劑量或實測活動範圍；八區有日期不能證明有效劑量、完成或減傷。
- 每日可用時間是上限。長期固定高強度球日若無可行肌力槽，明確提示目標衝突，不能為了填滿而強塞課；每2–4週應以實作及翌日反應回顧，不自動漸進。
- 問卷直接顯示球量／強度；恢復狀態在身體感受頂部，僅有痠痛時再顯示影響程度。第三步和預覽共用精簡條件摘要；日期詳情直接顯示一句安排原因，延用三步和精簡清單。
- 恢復狀態、痠痛影響程度及流程熟悉度只保留在本機私人問卷／完整快照，不加進公開或雲端bounded weeklyIntent。既有課表與有紀錄日期不自動改寫。

## 細分加強部位

加強部位`targetRegions`最多4項，保留legs/posterior/upper/core並加入前鋸肌、肩胛穩定、旋轉肌群、胸部、背部、前臂控制、臀肌、股四頭、腿後側、內收肌與小腿。僵硬／痠痛仍各最多2項。細項在問卷收合顯示，選入內容在摘要可見，不增加步驟。

`trainingTargets.js`用受信任目錄動作對應相關訓練，不從自訂名稱猜肌肉。前鋸肌優先C07，無彈力繩／滑輪時A07作專項控制；旋轉肌群C05、肩胛C06、前臂C09/C08、小腿B07/B08用原有單一輔助槽輪替，不疊加主課。輪替參考近兩週既有安排及本段先前日期，不當成已完成。內收肌可優先側弓步，臀肌可優先臀橋；健康、球日、賽前熟悉度、疲勞與時間仍優先。

日期預覽的加強部位面板依實際主項／輔助列日期，將A12/A13中的前鋸／肩胛啟動與專項訓練分開。沒有C07/A07專項時，不能用一般推胸或暖身冒充前鋸肌已排。多選不保證當週全排；未排項目明示限制，並保留八段動態拉伸開場。肌肉參與不代表孤立刺激或實測改善。

雲端沿用原bounded weeklyIntent欄位，目標白名單及長度上限同步擴充到4；舊兩項仍有效。Firestore規則須先部署，前端才發布，避免新選擇儲存失敗；未放寬帳號隔離或私人資料白名單。
