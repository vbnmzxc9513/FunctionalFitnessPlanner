# 訓練紀錄與調整實作計畫

本輪優先把「課前檢查 → 實際訓練紀錄 → 翌日回覆 → 下次調整」串起來。原有免費排課、BYOK、公開分享與完成紀錄仍可使用；不啟用付費 AI 體驗。

## 逐動作紀錄

- 正式組記錄實際次數／時間、左右側、阻力方式、公斤計算方式、餘力、動作品質及症狀。
- 空白不當作已完成，準備組不算正式組，單側動作不取左右平均。
- 保存當時的處方快照，包括組數、次數範圍、單位、左右側、階段與休息；重新排課不改寫舊快照。
- 保存實際紀錄不自動代表動作品質良好或適合進階。

## 每日狀態與今天的安排

- 記錄睡眠、疲勞、痠痛、症狀、前一天球局時長／RPE與今天球量。
- 缺資料時保持未知。門檻是保守編排規則，不是醫療診斷、恢復放行或傷害預測。
- 明確呈現維持、減量、恢復或休息理由；使用者確認後才調整今天尚未完成的課表。
- 不增加動作、組數或跳躍，不改已完成的處方；已排休息不能因自評精神好而升級。

## 下次訓練建議

- 比較同一動作、阻力方式與描述、公斤計算方式、處方、左右側和日期。
- 缺少翌日反應、餘力或品質時先維持；疲勞、症狀或限制優先。
- 至少兩個不同日期的合格紀錄，且翌日沒有惡化，才提出一次只改一個變數的進階建議。
- 優先在既有次數範圍內增加次數；重量增量需器材資訊，不虛構公斤，也不自動套用。
- 跳躍、步伐、反應、活動度與拉伸不套用肌力加重規則。

## 保存、隱私與驗收

- 登入資料按 UID 保存；訪客升級可轉移，已有紀錄不被重試匯入覆蓋。
- 未登入預覽的紀錄在分頁保存；選擇登入採用時，課表、勾選與合法紀錄原子儲存。
- 訓練紀錄、每日狀態與症狀不加入公開圖片／連結，也不自動傳給 AI。
- 單元測試覆蓋左右差異、缺資料、不同阻力、症狀、日期、雙重進階與減量。
- Firestore 模擬器驗證完整型別、隔離、原子保存與歷史快照；手機／電腦測試表單、重整、翌日回覆、登入採用與舊功能。

Sub-agents 分工：規則與驗證、資料保存、訓練畫面、App 串接。主 agent 做 code review、修正、測試並部署。
